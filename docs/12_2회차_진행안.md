# 2회차 진행안 — 흩어진 기록에 구조를 더하는 날

**90분 · 단계: 구조 · 워크북 `/session?n=2`**

> v2 — 회의록→구조 실습은 유지하되 **자기 회의록 우선**(샘플은 없는 사람용),
> 결과의 명시 저장(Supabase)과 **클래스 플랫폼(class_posts) 기록**이 추가됐습니다.

---

## 이 회차의 목표

**지어낸 항목을 눈으로 잡아낸다 — 후보를 넓게 뽑고, 규칙을 넣어 줄어드는 것을 확인한다.**

끝났을 때 상태:
- 규칙 없이 뽑은 개수(s2.count_before) vs 규칙 넣고 뽑은 개수(s2.count_after)의 차이를 설명할 수 있음
- 근거문장이 붙은 최종 액션아이템 표(s2.action_items)를 Supabase에 명시 저장
- 클래스 플랫폼에 학습 기록 글 1건 (워크북에서 다른 SaaS DB로 직접 쓰기 첫 경험)

## 강사 준비물 체크

- [ ] 클래스 연동 사전 확인 — 강사 계정으로 **클래스 계정 연결 → 글 저장 → 클래스 사이트에서 확인**까지 1회 완주
  - 로그인 후 클래스 사이트로 튕기면: 클래스 Supabase Redirect URLs에 `…/class-auth-callback.html` 등록을 관리자에게 요청 (README 배포 절 참고). **미해결이면 이 실습은 시연으로 대체**
- [ ] 샘플 회의록(문서 04) 실습장 게시 확인 — 자기 회의록 없는 수강생용
- [ ] 함정 표(문서 04의 E절) 슬라이드
- [ ] 1회차 숙제(읽힐 원본) `/admin`에서 훑어두기

## 타임테이블

| 시간 | 블록 | 핵심 |
|---|---|---|
| 0–10 | 체크인 | 1회차 숙제 공유 + "이 워크북도 DB다" (실습 0) |
| 10–25 | 개념 | 백지 vs 양식 · 빈칸 규칙 · 근거문장 |
| 25–40 | 데모 | 넓게 뽑기(20+) → 규칙 넣기(13~15) → 검증 |
| 40–75 | 실습 | 워크북 실습 1~3 + 클래스 기록 |
| 75–90 | 정리 | 함정 대조 + [모두 저장] + 숙제 |

## [0–10] 체크인 + 실습 0

> "지난주 입력한 게 어디 갔을까요? 이 워크북도 여러분이 오늘 배우는 것과 같은 구조입니다 —
> 입력 한 칸 = DB 한 행. 홈의 '이 워크북도 하나의 연결 사례입니다' 섹션이 그 설명입니다."

실습 0(s2.db_reflection)을 그 자리에서 한 줄 쓰게 한다.

## [10–25] 개념

화이트보드 실연 — 백지에 "회의 내용 정리해줘" vs 빈칸이 정해진 양식. 핵심 세 가지:
- **기본값을 미리 정한다** — 상태 없으면 '시작 전', 우선순위 없으면 '보통'
- **근거문장** — 실무 DB엔 없는 교육용 칸. 지어낸 행을 잡는 장치
- ★ 환각 방지 한 줄: **"추측해서 채우지 마라. 모르면 빈칸으로 두라."**

## [25–40] 데모 — 이 회차의 전부

1. **나쁜 요청 먼저**: 규칙 없이 "액션아이템 뽑아줘" → 20개+ 나온 결과를 그대로 붙인다. "좋아 보입니까?"
2. **한 줄씩 검증**: 결정 안 된 논의(케이터링·"검토만")·이미 처리된 건을 짚는다.
   > "이 세 개, 회의에서 아무도 하기로 하지 않았습니다. 다음 주에 **지연**으로 뜹니다."
3. **규칙 넣고 다시**: 프롬프트 카드(2회차)의 규칙 포함 버전 → 13~15개. "사라진 게 아니라 원래 없던 겁니다."
4. **근거 검증**: "근거문장이 원문에 실제로 있는지 확인해줘" → 못 찾은 행 = 지어낸 행.

## [40–75] 실습

> "자기 팀 회의록이 있으면 그걸로, 없으면 실습장의 샘플 회의록 3건으로.
> 순서: 넓게 뽑기 → 개수 기록 → 규칙 넣고 다시 → 최종 표 → **[최종 결과 저장]** 버튼."

순회 체크포인트:
- **10분** — count_before가 비어 있는 사람: 넓게 뽑기를 건너뛰고 규칙부터 하면 대비 학습이 사라짐. 순서 교정
- **20분** — 20개 넘게 유지 중인 사람: 규칙 2(논의만 된 건 제외) 누락
- **30분** — 클래스 계정 연결 시작시킴 (연결→복귀→글 저장→확인 4단계가 화면에 안내됨)

막힘 대응:
| 증상 | 대응 |
|---|---|
| 클래스 로그인 후 **클래스 사이트로 이동해버림** | 클래스 플랫폼 허용 목록 문제 — 화면의 안내 문구대로 관리자 요청 대상. 오늘은 시연으로 대체 |
| 클래스 글 저장 실패 | 수강 참여 권한(클래스 등록 여부) 확인 |
| 근거문장을 요약해서 적음 | "원문 그대로 복사"가 규칙 — 요약은 검증이 안 됨 |
| 자기 회의록이 구두 회의뿐 | 샘플 회의록으로 전환, 숙제에서 기록 습관부터 |

## [75–90] 정리 — 함정 대조 (하이라이트)

문서 04 E절 함정 표를 띄우고 "이거 걸린 사람?" 손들기.
> "여러분이 못한 게 아니라 원래 걸리게 만든 회의록입니다. 실제 회의록은 더 지저분합니다."

- 샘플 기준 적정 개수 **13~15개** (20+ = 논의를 액션으로, 10− = 누락)
- ★ 전원 **[모두 저장]** + 클래스 글 저장 여부 확인
- 숙제: 다른 회의록 1건으로 같은 작업, **어디서 막혔는지**를 기록

## 시간 조절

자르는 순서: 클래스 기록(→숙제로) → 함정 대조 8개→3개 → 실습 0.
**절대 자르지 말 것**: 데모 1~3(넓게→규칙→차이), 최종 표 명시 저장.
