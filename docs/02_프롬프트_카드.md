# 업무 연결 프롬프트 카드 — 읽고, 구조화하고, 연결하는 문장들

회차별로 필요한 프롬프트만 잘라서 사용합니다. [대괄호] 부분만 각자 상황에 맞게 바꾸고,
실행 전에는 **읽을 범위·결과 형식·사람의 확인 지점**을 확인합니다.

## 사용하는 위치와 결과를 보는 위치

프롬프트 카드는 실행 버튼이 아닙니다. 워크북에서 `복사`한 뒤 Claude 대화창에 붙여넣어 실행합니다.

    워크북 프롬프트 복사 → Claude에서 실행 → Claude 또는 연결한 업무 도구에서 결과 확인
                                  → 회차별 워크북 결과 칸에 실행 결과 기록

- 일반 요약·분석: Claude 대화창에서 결과를 확인하고 워크북에 기록합니다.
- Asana·Notion·Slack 발송: Claude 결과와 실제 업무 도구 화면을 함께 확인합니다.
- Slack 웹훅 받기: Slack 테스트 메시지 작성 후 3회차 워크북의 Slack 수신함에서 `event_id·channel_id·text`를 확인합니다. 운영자는 필요하면 Vercel 로그도 확인합니다.
- 워크북에 직접 적은 결과: 로그인한 사용자의 Supabase `entries`에 자동 저장됩니다.

현재 워크북은 Claude의 답변을 자동으로 가져오지 않습니다. Claude에 해당 업무 도구 연결 또는 별도 API 도구가 설정되어 있어야 실제 데이터를 읽고 쓸 수 있습니다.

## 0. 모든 프롬프트의 공통 골격

좋은 요청은 네 칸이 채워져 있습니다.

    [어디서]  원본 도구·페이지·프로젝트·채널
    [무엇을]  읽거나 보낼 범위
    [어떤 형식으로]  결과의 열·문장·필드
    [어디로]  화면·페이지·채널·태스크

목적지별 기본 형태:

- Asana: 프로젝트의 태스크
- Notion: 특정 페이지 또는 데이터베이스의 행
- Slack: Channel ID에 보낼 메시지 또는 이벤트 수신
- Supabase: 연결 결과와 로그를 저장하는 한 행

## 1회차 — 업무 원본 읽기

> 첫날은 읽기만 합니다. 실제 DB에 쓰거나 채널에 발행하지 않고, 원본의 범위·맥락·근거를 확인합니다.

### 읽을 수 있는 원본 목록

    노션 「AX 실습장」 안에서 현재 내가 접근할 수 있는 페이지와 데이터베이스를 찾아줘.

    본문 내용은 아직 읽지 말고 아래 표로만 보여줘:
    - 원본 이름
    - 도구와 위치
    - 자료 유형
    - 마지막 수정일
    - 다음 단계에서 읽어볼 이유

    내 권한 밖의 자료는 '접근 불가'라고 표시하고 추측하지 마.

### 원본을 업무 맥락으로 요약하기

    노션 「[페이지명]」 한 페이지만 읽어줘.

    아래 순서로 업무 맥락을 요약해줘:
    1. 이 자료의 목적
    2. 핵심 내용 3~5개
    3. 이미 정해진 일
    4. 아직 정해지지 않은 일
    5. 다음 단계에서 확인할 질문

    원문에 직접 적힌 내용만 사용하고, 담당자·날짜·수량을 추측하지 마.
    각 항목 뒤에 근거가 된 원문 문장을 붙여줘.
    확인할 수 없는 값은 '미확인'으로 표시해줘.

### 근거와 빈칸 확인하기

    방금 만든 업무 맥락 요약을 원본과 대조해서 검수해줘.

    표의 열은 [요약 항목 / 근거 원문 / 확인 상태 / 사람이 확인할 질문]으로 해줘.
    원본에 없는 내용, 다른 페이지의 내용, 추측한 담당자·날짜·수량이 섞였는지 확인해줘.
    근거가 없는 항목은 '확인 필요'로 표시해줘.

## 2회차 — 회의록 → 업무 DB

### 규칙 없이 먼저

    「AX 실습장」의 샘플 회의록 3건을 읽고 액션아이템을 뽑아줘.

### 규칙을 넣고 다시

    위 회의록 3건을 읽고 액션아이템만 표로 만들어줘.
    열은 작업 이름 / 담당자 / 상태 / 마감일 / 우선순위 / 유형 / 세부내용 / 근거문장 / 출처 회의록.

    담당자·날짜는 원문에 있을 때만 채워줘.
    논의만 되고 결정되지 않은 것은 액션아이템이 아니야.
    근거문장이 없는 행은 만들지 마.

### Supabase 구조 읽기

    이 워크북의 Supabase 구조를 비개발자도 이해할 수 있게 설명해줘.
    profiles는 로그인한 사람, entries는 user_id·item_key·value로 저장되는 입력,
    RLS는 본인의 답만 읽고 쓰게 하는 권한 규칙으로 설명해줘.
    1회차 체크인 답변이 entries에 저장되는 예시 한 행도 보여줘.

### 미리보기 후 등재

    이 항목들을 내가 복제한 「내 업무(연습용)」 DB에 등재할 거야.
    먼저 1건만 어떤 값으로 넣을지 보여줘.
    내가 진행이라고 하면 그때 실제로 등재해.

## 3회차 — Asana·Notion·Slack 실제 연결

> 토큰은 Vercel 서버에만 있습니다. 수강생은 대상 URL·ID와 권한만 준비합니다.

### 0단계 — 연결값 확인

    운영자가 Vercel 환경변수에 다음 값을 설정했다고 가정해줘:
    ASANA_TOKEN_BOT / NOTION_TOKEN / SLACK_BOT_TOKEN / SLACK_SIGNING_SECRET

    토큰의 실제 값은 절대 보여주지 말고 설정 여부만 확인해줘.
    수강생이 직접 넣을 값은 Asana Project GID, Notion Page ID,
    Slack Channel ID, Slack Events API Request URL로 구분해줘.

### 1단계 — Asana 봇을 프로젝트에 초대하고 읽기

    Asana에서 Project GID [Project GID]의 프로젝트를 읽기 전용으로 확인해줘.
    운영자 서버의 ASANA_TOKEN_BOT을 사용하되 토큰 값은 노출하지 마.

    프로젝트 이름과 워크스페이스를 확인하고, 태스크 최대 3개를
    [태스크명 / 담당자 / 마감일 / 완료 여부 / Asana URL]로 보여줘.
    봇이 프로젝트 멤버로 초대되지 않았다면 필요한 조치를 알려줘.
    오늘은 태스크를 만들거나 수정하지 마.

### 2단계 — Notion 앱을 원하는 페이지에 연결하고 읽기

    Notion Page ID [Page ID]를 읽기 전용으로 확인해줘.
    페이지 우측 상단 ··· → 연결 추가에서 기존 앱을 연결했다.
    운영자 서버의 NOTION_TOKEN을 사용하되 토큰 값은 노출하지 마.

    페이지 제목과 본문 블록을 읽고 핵심 내용 3~5개로 요약해줘.
    데이터베이스라면 행 3개를 [제목 / 상태 / 담당자 / 날짜]로 보여줘.
    연결되지 않았거나 Read content 권한이 없으면 원인과 해결 방법을 알려줘.
    오늘은 페이지를 수정하거나 새 페이지를 만들지 마.

### 3단계 — Slack 봇으로 원하는 채널에 보내기

    Slack Channel ID [Channel ID]에 보낼 메시지를 먼저 미리 보여줘.
    내가 확인하면 운영자 서버의 SLACK_BOT_TOKEN으로 전송해줘.
    토큰 값은 절대 노출하지 마.

    메시지는 제목 1줄과 핵심 불릿 3~5개로 짧게 만들어줘.
    전송 후 응답의 channel과 ts를 보여줘.
    봇이 채널에 없거나 권한이 없으면 전송하지 말고 해결 방법을 알려줘.

### 4단계 — Slack 채널 메시지를 Vercel 웹훅으로 받기

    Slack Events API 실습용 서버 흐름을 설계해줘.
    Request URL은 [Vercel의 Slack Events 엔드포인트],
    대상 채널은 [Channel ID]야.

    SLACK_SIGNING_SECRET으로 요청 서명을 검증하고,
    url_verification challenge에는 200으로 응답해줘.
    event_callback에서는 channel_id, user, text, event_ts, event_id를 추출해줘.
    대상 채널이 아니거나 봇이 보낸 메시지면 무시해줘.
    Slack에는 빠르게 200을 반환하고 처리 결과를 로그로 남겨줘.

    테스트 메시지 AX-WEBHOOK-TEST를 보낸 뒤 성공 여부를 판단할 기준도 알려줘.

### 5단계 — 같은 원본을 세 목적지에 맞게 바꾸기

    원본 [Asana 태스크 또는 Notion 페이지]를 아래 세 목적지에 맞게 변환해줘.
    열은 [원본 필드 / Asana에 남길 값 / Notion에 기록할 값 /
    Slack에 보낼 문장 / 사람이 확인할 지점]으로 해줘.

    Asana는 실행할 태스크, Notion은 다시 찾을 기록,
    Slack은 지금 읽고 행동할 메시지로 만들어줘.
    담당자·마감일·공개 범위가 원본에 없으면 '확인 필요'로 표시해줘.

### 6단계 — 연결 레시피로 저장

    방금 한 연결 실습을 다음 사람이 다시 실행할 수 있는 레시피로 정리해줘.
    원본 범위, 봇·앱 초대 위치, 목적지 ID, Vercel 환경변수 이름,
    사람의 확인 항목, 실패 시 파일·샘플 JSON 전환 방법을 포함해줘.
    실제 토큰 값은 쓰지 말고 [Project GID], [Page ID], [Channel ID]로 남겨줘.

## 4회차 — 개인 루틴과 데스크톱 확장

### 수신함 정리

    [다운로드 폴더 / 카카오톡 받은 파일]의 반복 패턴을 찾아
    파일명 패턴 → 이동할 폴더 형태로 규칙을 제안해줘.
    애매한 파일은 판단 필요로 남기고 아직 옮기지는 마.

### 일일 로그

    오늘 수정한 프로젝트 파일, 오늘 받은 파일, 오늘 노션에서 만든 페이지를 모아
    [오늘 한 일 / 받은 자료 / 결정·메모 / 내일 할 일] 형식으로 기록해줘.
    흔적으로 확인되는 내용만 사용해줘.

### 데스크톱 파일 자동정리

    Downloads, 카카오톡 받은 파일 폴더, 프로젝트 폴더를 대상으로
    관찰 → 분류 규칙 제안 → Dry Run → 사람 승인 → 이동 순서의 설계안을 만들어줘.
    삭제하지 않고 이동만 하며, 애매한 파일은 보류하고 undo 방법을 남겨줘.

## 막혔을 때 쓰는 문장

| 상황 | 다시 요청할 문장 |
|---|---|
| 엉뚱한 원본을 가져옴 | 어디서 가져온 건지 원본 URL·ID부터 알려줘 |
| 권한이 없음 | 필요한 초대 위치와 권한 이름을 알려줘. 토큰 값은 요구하지 마 |
| 결과가 너무 김 | 핵심만 5줄로 줄이고 근거 ID를 남겨줘 |
| 지어낸 것 같음 | 근거 원문 또는 API 응답 필드를 각 항목에 붙여줘 |
| Slack 이벤트가 반복됨 | 봇 메시지와 이미 처리한 event_id를 제외해줘 |
| 연결이 안 됨 | 상태 코드·오류 문장·대상 ID만 보여줘. 토큰은 보여주지 마 |
