# 프롬프트 카드 — 실습에서 그대로 복사해 쓰는 문장들

회차별로 필요한 프롬프트만 잘라서 배포한다. `[대괄호]` 부분만 각자 상황에 맞게 바꾼다.

---

## 0. 모든 프롬프트의 공통 골격

좋은 요청은 이 4칸이 다 채워져 있다. 실습 중 막히면 **어느 칸이 비었는지** 먼저 확인한다.

```
[어디서]  노션 「내 업무(연습용)」 DB에서
[무엇을]  이번 주 마감인 항목만
[어떤 형식으로]  작업 이름 / 담당자 / 상태 / 마감일 4개 열의 표로
[어디로]  화면에 보여줘 (아직 아무데도 쓰지 마)
```

### 잘 긁히는 요청 vs 안 긁히는 요청

| ❌ 안 긁힘 | ✅ 잘 긁힘 | 차이 |
|---|---|---|
| "회의록 정리해줘" | "「AX 실습장」의 샘플 회의록 3건을 읽고, 액션아이템만 표로" | 출처와 범위가 있다 |
| "우리 팀 현황 알려줘" | "「내 업무(연습용)」에서 상태가 '진행 중'인 항목 전부" | DB 이름과 조건이 있다 |
| "잘 정리해줘" | "작업 이름 / 담당자 / 마감일 3개 열로, 마감일 빠른 순" | 형식이 있다 |
| "노션에 올려줘" | "표로 먼저 보여주고, 내가 확인하면 그때 등재해줘" | 확인 지점이 있다 |

## 1회차 — 행사 퀴즈 콘텐츠

> 2026년 5월에 크롬 확장 프로그램(notion-extractor)으로 만들었던 콘텐츠를, 확장 프로그램 없이 다시 만듭니다.

### 준비 — 연결 확인
```
노션에서 「부스터스 크루 소개」 페이지를 찾아서, 어떤 데이터베이스들이 들어 있는지
목록만 알려줘. 내용은 아직 읽지 마.
```
> 이게 되면 커넥터 연결 성공. 안 되면 플랜 B(파일 업로드)로 전환.

### 과제 A — WHO AM I 15문항 (힌트 3단 차등점수)
```
노션 「부스터스 크루 소개」의 크루 프로필 데이터를 읽어줘.

그걸로 'WHO AM I' 퀴즈를 15문항 만들어줘. 규칙은 이렇게:

- 한 문항 = 힌트 3개 + 정답 1명
- 힌트는 어려운 것 → 쉬운 것 순서로. 힌트①은 3점, 힌트②는 2점, 힌트③은 1점.
  (힌트③까지 들으면 대부분 맞힐 수 있게)
- 힌트에 이름, 부서명 전체, 연락처는 절대 넣지 말 것
- 소개글에 없는 내용은 지어내지 말 것. 힌트 3개를 못 채우면 그 사람은 건너뛰기
- 정답은 이니셜로 표기 (예: 도OO)

출력은 [번호 / 힌트①(3점) / 힌트②(2점) / 힌트③(1점) / 정답] 표로.
```
> **왜 점수를 차등하나**: 진행할 때 긴장감이 생깁니다. 그리고 "형식을 얼마나 구체적으로 줄 수 있는가"의 예시입니다.

### 과제 B — AI 예측 퀴즈 10인 ★
```
같은 크루 소개 데이터를 보고, 이번엔 반대로 해줘.

'AI가 예측하는 이 사람' 퀴즈를 10인분 만들어줘.
자기소개에 **적혀 있지 않은** 것을, 적혀 있는 내용으로부터 추측해서 쓰는 거야.

- 한 사람당: 소속 + "이 사람은 이럴 것 같습니다" 예측 3~4줄 + 정답(이니셜) + 재미 포인트
- 예측은 소개글의 단서에서 출발하되, 소개글에 없는 영역으로 확장할 것
  (예: 주말에 뭘 할 것 같은지, 회의에서 어떤 말을 자주 할 것 같은지)
- 무례하거나 외모·나이·가족에 대한 추측은 금지

출력은 [번호 / 소속 / AI의 예측 / 정답 / 재미 포인트] 표로.
```
> **★ 강사가 여기서 반드시 물을 것**
> "이거 재밌죠? 그런데 지금 AI가 **없는 얘기를 지어낸** 겁니다.
> 오늘은 그게 재미인데, **다음 주에 회의록으로 같은 일이 벌어지면 어떻게 될까요?**"
>
> 1회차와 2회차를 잇는 다리입니다. A(지어내면 안 됨)와 B(지어내는 게 목적)를 나란히 놓는 게 이 과제의 설계 의도입니다.

### 과제 C — 크로스 퀴즈 10문항
```
크루 소개 데이터 전체를 보고, 두 사람 이상의 '숨은 공통점'을 찾아줘.

- 한 문항 = 질문 + 정답(공통점과 해당 인물들)
- 예: "같은 취미를 가진 세 사람은?", "출신 지역이 같은 두 사람은?"
- 억지로 만들지 말 것. 공통점마다 **근거가 된 소개글 문장**을 함께 붙여줘
- 근거를 못 붙이는 항목은 아예 빼

출력은 [번호 / 질문 / 정답(공통점·인물) / 근거 문장] 표로.
```
> **수업 포인트**: "근거 문장을 붙여줘"가 2회차의 핵심 기술입니다. 여기서 미리 한 번 씁니다.

### 실패 시연용 (강사 데모)
```
우리 회사 전 직원 연봉 정리해줘
```
> 접근 못 한다. **AI가 볼 수 있는 범위 = 내 계정 권한 범위**라는 걸 몸으로 알게 하는 데모.

## 2회차 — 회의록 → 업무 DB

### 1단계 — 긁기
```
노션 「AX 실습장」 아래에 있는 샘플 회의록 3건을 찾아줘.
제목과 날짜만 먼저 목록으로 보여줘.
```

### 2단계 — 액션아이템 추출 (핵심 프롬프트)
```
위 회의록 3건을 읽고, 액션아이템만 뽑아서 표로 만들어줘.

표의 열은 「내 업무(연습용)」 DB 형식에 맞춰서:
작업 이름 / 담당자 / 상태 / 마감일 / 우선순위 / 유형 / 세부내용 / 근거문장 / 출처 회의록

작성 규칙:
- 작업 이름은 동사로 끝맺기 ("장소 예약 확인", "견적서 요청")
- 상태는 시작 전 / 진행 중 / 완료 중 하나. 회의록에 안 나오면 '시작 전'
- 담당자는 회의록에 이름이 명시된 경우만. 없으면 빈칸
- 마감일: "다음 주까지" 같은 표현은 그 회의의 날짜를 기준으로 실제 날짜로 환산.
  기준이 없으면 빈칸
- 우선순위는 긴급/높음/보통/낮음 중 하나. 명시 없으면 '보통'
- 유형은 반드시 이 목록 안에서만 고를 것:
  회의, 업무요청, 확인·검토, 자료작성, 외부협의, 일정조율, 승인대기, 기타
- 근거문장: 이 항목이 나온 회의록 원문 문장을 그대로 복사해서 넣을 것
- 출처 회의록: 회의록 제목과 날짜

중요한 규칙 두 개:
1. **추측해서 채우지 마라. 모르면 빈칸으로 두라.**
   근거문장을 못 채우는 항목은 아예 표에 넣지 마라.
2. **논의만 되고 결정되지 않은 것은 액션아이템이 아니다.**
   "검토해보겠다", "다음에 얘기하자", "아직 정해진 건 없다"로 끝난 항목은 빼라.
```
> **강사 메모**: 규칙 2를 빼고 한 번 돌려서 20개가 넘게 나오는 걸 보여준 뒤,
> 규칙 2를 넣고 다시 돌리면 13~15개로 줄어든다. 이 대비가 2회차에서 가장 잘 먹힌다.

### 3단계 — 검수 (수강생이 직접)
```
방금 만든 표에서, 근거문장이 회의록에 실제로 있는지 다시 확인해줘.
원문에서 못 찾은 행이 있으면 그 행만 따로 알려줘.
```
> **수업 포인트**: 여기서 걸리는 행이 나오면 "AI가 지어냈다"를 눈으로 보는 순간. 반드시 짚고 넘어간다.

### 4단계 — 등재 (미리보기 → 1건 → 나머지)
```
이제 이 항목들을 노션 [내가 복제한 「내 업무(연습용)」] DB에 등재할 거야.

먼저 1건만 등재해줘. 어떤 항목을 어떤 값으로 넣을지 먼저 보여주고,
내가 "진행"이라고 하면 그때 실제로 등재해.
```
그다음:
```
좋아, 나머지도 같은 방식으로 등재해줘.
등재한 항목에는 비고란에 "AX실습-[오늘날짜]" 라고 남겨줘.
```
> 비고 표시 = 나중에 실습 데이터만 골라 지울 수 있는 되돌리기 장치.

## 3회차 — 주간 리포트 → 슬랙

### 1단계 — 이번 주 데이터 긁기
```
노션 「내 업무(연습용)」에서 다음을 가져와줘:

- 이번 주에 완료된 항목
- 현재 진행 중인 항목
- 마감일이 지났는데 완료가 아닌 항목

각각 작업 이름 / 담당자 / 마감일 / 상태로 표를 나눠서 보여줘.
```

### 2단계 — 주간 요약 생성
```
위 데이터로 주간 업무 리포트 초안을 써줘. 구성은:

1. 이번 주 완료 (건수 + 목록, 한 줄씩)
2. 진행 중 (건수 + 목록, 예상 완료 시점 있으면 같이)
3. 지연 (건수 + 목록) — 각 건마다 '지연 사유'와 '다음 액션' 칸을 비워두고 만들어줘.
   사유는 데이터에 없으니 내가 채운다.

읽는 사람은 팀장이고, 30초 안에 상황 판단이 되어야 해.
숫자 없는 형용사("많이", "잘")는 쓰지 마.
```
> **수업 포인트**: 지연 사유를 AI가 지어내게 두면 안 된다. **빈칸으로 받아 사람이 채우는 것**이 정답.

### 3단계 — 슬랙 문체 변환
```
이 리포트를 슬랙에 올릴 형태로 바꿔줘.

- 첫 줄은 제목 한 줄 (주차 + 팀명)
- 항목은 불릿으로, 각 줄 40자 이내
- 완료/진행/지연에 각각 이모지 하나씩
- 지연 항목의 담당자는 멘션 자리를 @이름 형태로 남겨줘 (내가 실제 멘션으로 바꿀게)
- 전체 15줄 이내. 길면 상세는 스레드로 뺄 수 있게 나눠줘
```

### 4단계 — 리허설 발송
```
이 내용을 슬랙에서 나 자신에게 DM으로 보내줘.
보내기 전에 최종 문구를 한 번 더 보여줘.
```
> 채널 발행은 **본인이 슬랙에서 직접** 붙여넣어 게시한다. 자동 채널 발송은 강의 범위 밖.

### 5단계 — 레시피로 저장
```
방금 우리가 한 1~4단계 전체를, 다음 주에 내가 한 번에 다시 쓸 수 있는
프롬프트 한 덩어리로 정리해줘.

날짜처럼 매주 바뀌는 부분은 [이번 주] 같은 대괄호 자리표시자로 남겨줘.
```
> 결과를 노션 「내 프롬프트 라이브러리」나 개인 메모에 저장 → 매주 붙여넣기.

## 4회차 — 개인 루틴

### 수신함 정리
```
[다운로드 폴더 / 카톡 받은 파일] 안에 있는 파일들을 살펴보고,
어떤 종류가 반복해서 들어오는지 분류 규칙을 제안해줘.

- 파일명 패턴 → 이동할 폴더 형태로
- 애매한 건 '판단 필요'로 따로 빼줘
- 아직 옮기지는 마. 규칙안만 먼저 보여줘
```

### 일일 로그
```
오늘 내가 작업한 흔적을 모아서 하루 기록을 만들어줘.

- 오늘 수정한 프로젝트 파일
- 오늘 받은 파일
- 오늘 노션에서 내가 만들거나 수정한 페이지

형식은 [오늘 한 일 / 받은 자료 / 결정·메모 / 내일 할 일] 4단락으로.
추측은 넣지 말고, 흔적으로 확인되는 것만.
```

### 주간 회고
```
이번 주 일일 로그 5개를 모아서 KPT 회고 초안을 만들어줘.

- Keep: 계속할 것
- Problem: 반복해서 걸린 것
- Try: 다음 주에 시도할 것

각 항목마다 근거가 된 날짜를 괄호로 표시해줘. 근거 없는 항목은 넣지 마.
```

## 막혔을 때 쓰는 문장 (전 회차 공통)

| 상황 | 이렇게 말한다 |
|---|---|
| 엉뚱한 걸 가져왔다 | "어디서 가져온 건지 출처를 먼저 알려줘" |
| 결과가 너무 길다 | "핵심만 5줄로 줄여줘" |
| 형식이 매번 다르다 | "지금 형식을 템플릿으로 고정하고, 앞으로 이 형식으로만 답해" |
| 지어낸 것 같다 | "근거가 된 원문 문장을 각 항목마다 붙여줘" |
| 실수로 뭔가 썼다 | "방금 만든 항목들 목록을 보여줘" → 노션에서 직접 삭제 |
| 아예 접근이 안 된다 | 커넥터 연결 상태 확인 → 안 되면 파일 다운로드 후 업로드 |
