# 1회차 진행안 — AI에게 업무 원본을 읽히는 날

**90분 · 전사 크루(비개발) · 실습 소재: 업무 원본 읽기와 근거 확인**

**비유로 시작하기**: 커넥터는 회사 전체 열쇠가 아니라, 내 권한으로 열 수 있는 업무 자료실의 문만 함께 여는 읽기 권한 카드입니다.

---

## 이 회차의 목표

1회차는 재미있는 결과물을 많이 만드는 시간이 아닙니다. **AI가 내 업무 원본을 어디까지 읽을 수 있는지 확인하고, 읽은 내용을 근거와 함께 요약하는 시간**입니다.

**끝났을 때 상태**

- 내가 읽을 수 있는 원본과 읽지 않을 범위를 말할 수 있음
- 업무 원본 1건을 목적·핵심 내용·결정사항·열린 질문으로 요약함
- 핵심 내용마다 원문 근거를 붙이고, 확인할 수 없는 값은 빈칸으로 남김
- 가져온 원본 요약과 근거를 워크북 Supabase에 저장하고 다시 확인함
- 2회차에 어떤 데이터 한 행으로 바꿀지 한 문장으로 정함

---

## 강사 준비물 체크 (강의 30분 전)

- [ ] 수강생이 선택할 수 있는 Notion 페이지·Slack 원본·Asana 프로젝트를 준비
- [ ] 노션·슬랙·아사나 연결과 워크북 저장 상태를 강사 화면에서 미리 1회 확인
- [ ] 원본을 가져오고 워크북에 저장하는 실습 화면과, 접근할 수 없는 자료를 요청할 화면을 준비
- [ ] 프롬프트 카드 `s1a`, `s1b`, `s1c` 확인
- [ ] 슬랙 `#ax-실습` 완성물 스레드 개설
- [ ] 민감정보가 없는 샘플만 사용하고, 실제 운영 DB는 열지 않음

## [0–10] 체크인 — 없어졌으면 하는 반복 업무

입력 칸에는 다음 두 가지를 한 줄로 적게 합니다.

1. 반복해서 하는 업무는 무엇인가?
2. 그 업무의 원본은 지금 어디에 있는가?

예시:

> 매주 팀 진행상황을 정리한다. 원본은 노션 업무 DB와 슬랙 대화에 있다.

여기서 자동화 설계를 시작하지 않습니다. 오늘은 **원본이 실제로 존재하고, 내가 접근할 수 있는지**만 확인한다고 안내합니다.

---

## [10–25] 개념 — 읽을 수 있어야 연결할 수 있다

### 1. 커넥터는 읽기 범위를 정하는 장치다

- 노션 페이지, 슬랙 채널·DM, 아사나 프로젝트는 각각 접근 범위가 다르다.
- 내가 볼 수 없는 자료는 AI도 볼 수 없다.
- 연결했다고 해서 회사 전체 자료를 읽는 것이 아니다.

### 2. 첫날부터 작은 읽기·쓰기 루프를 닫는다

| 단계 | 오늘 | 다음 회차 |
|---|---|---|
| 가져오기 | 「AX 실습장」의 위치·범위·기존 문단 확인 | Asana·Slack까지 확장 |
| 수정 | 복제본의 연습 문단을 워크북에서 작게 수정 | 필드와 목적지별 형식으로 확장 |
| 원본 도구에 저장 | 변경 전후 미리보기 후 같은 Notion block ID에 저장 | 3회차에 Asana 태스크·Slack 메시지까지 확장 |
| 워크북에 기록 | 원본 스냅샷·근거·Notion 저장 영수증을 Supabase에 저장 | 최종 표와 연결 결과를 저장·재조회 |

### 3. 결과보다 근거가 먼저다

AI가 만든 문장이 그럴듯한지는 중요하지 않습니다. **원본의 어느 문장에서 나왔는지 확인할 수 있어야** 다음 단계로 보낼 수 있습니다.

---

## [25–40] 라이브 데모 — 원본에서 업무 맥락까지

### 데모 1 — 읽을 수 있는 원본 목록 (5분)

각자 복제한 「AX 실습장」을 1회차 실습 패널의 **수정할 문단 불러오기** 버튼으로 불러옵니다. 페이지 제목·block ID·기존 문장이 워크북에 나타나는 것을 먼저 확인합니다. 프롬프트 카드 `s1a`는 버튼 뒤에서 필요한 범위 확인 규칙을 설명할 때 참고합니다.

```text
연결 준비에서 지정한 원본 중 현재 내가 접근할 수 있는 페이지와 데이터베이스를 찾아줘.
본문을 읽는 경우에는 출처와 범위를 함께 표시하고, 이름·유형·다음에 읽어볼 이유를 목록으로 보여줘.
```

강사는 목록을 보면서 **읽을 것과 읽지 않을 것**을 구분합니다.

### 데모 2 — 업무 맥락 요약 (7분)

지정한 원본 1건만 골라 다음 네 칸으로 요약합니다. 샘플 회의록은 원본이 없을 때만 대체 자료로 사용합니다.

- 이 자료의 목적
- 핵심 내용
- 이미 정해진 일
- 아직 정해지지 않은 일

### 데모 3 — 근거와 빈칸 (3분)

핵심 내용 옆에 원문 문장을 붙입니다. 원문에 없는 담당자·날짜·수량은 비워둡니다.

### 데모 4 — 권한 범위 (5분)

접근할 수 없는 자료를 일부러 요청합니다. AI가 멈추는 이유를 설명하며 **연결의 범위가 곧 안전장치**라는 것을 보여줍니다.

## [40–75] 실습 — 업무 원본 읽기

수강생에게 이렇게 안내합니다.

> "오늘은 공용 페이지나 실제 팀 DB를 건드리지 않습니다. 내 「AX 실습장」 복제본의 연습 문단을 가져와 작은 수정을 만들고, 변경 전후를 확인한 뒤 같은 문단에 저장합니다."

### 실습 1 — 읽을 수 있는 원본 찾기 (10분)

1회차 실습 패널에서 「AX 실습장」 문단을 가져온 뒤, 페이지 제목·block ID·읽을 범위를 정리합니다.

기록할 것:

- 원본 이름
- 도구와 위치
- 읽을 기간·조건
- 이번 실습에서 제외할 자료

### 실습 2 — 원본을 업무 맥락으로 요약하기 (15분)

실습 2의 원본 입력란에 읽을 페이지명 또는 URL을 넣고, 원본 하나만 지정합니다. 프롬프트 카드 `s1b`는 요약 형식의 참고 레시피입니다.

결과는 아래 순서로 남깁니다.

1. 목적
2. 핵심 내용
3. 이미 정해진 일
4. 아직 정해지지 않은 일
5. 다음 단계에서 확인할 질문

### 실습 3 — 근거와 빈칸 확인하기 (10분)

가져온 요약 결과를 원본과 대조하고, 프롬프트 카드 `s1c`를 검수 질문의 참고 레시피로 사용합니다.

- 근거 문장이 붙어 있는가?
- 원본에 없는 값이 들어갔는가?
- 서로 다른 원본의 내용이 섞이지 않았는가?
- 사람이 확인해야 할 질문이 남아 있는가?

### 실습 4 — 같은 Notion 문단에 수정 저장하기 (5분)

수정 실습 문단을 짧게 고치고 **수정 미리보기**를 누릅니다. 기존 문장과 수정 후 문장을 비교한 뒤, 한 번 더 확인해 같은 block ID에 저장합니다.

마지막으로 원본 스냅샷·근거·Notion 저장 영수증이 Supabase에 남았는지 다시 읽습니다. Notion은 실제 업무 원본, Supabase는 실행 과정과 학습 기록을 맡는다는 차이를 확인합니다.

> 예: 회의에서 결정된 업무 한 건 / 고객 요청 한 건 / 콘텐츠 검수 한 건

## 순회 체크포인트

| 시점 | 확인할 것 | 막혔을 때 |
|---|---|---|
| 5분차 | 커넥터 연결 여부 | 연결 범위를 다시 선택하고, 안 되면 파일 업로드로 전환 |
| 15분차 | 원본 하나만 지정했는지 | 범위를 줄이고 기간·조건을 넣게 함 |
| 25분차 | 요약과 근거를 분리했는지 | 원문 문장을 직접 붙이게 함 |
| 35분차 | 미리보기의 block ID와 수정 전후가 맞는지 | 저장하지 말고 AX 실습장 복제본과 다시 대조 |
| 40분차 | 워크북에 저장했는지 | 저장 버튼을 누르고 다시 읽은 값 확인 |

### 자주 나오는 문제

| 증상 | 원인 | 대응 |
|---|---|---|
| 페이지를 못 찾음 | 접근 범위에 빠짐 | 커넥터 범위를 다시 설정하고, 안 되면 샘플 파일 사용 |
| 결과가 너무 넓음 | 원본·기간·조건이 없음 | 페이지 하나와 기간 하나만 남김 |
| 요약이 그럴듯하지만 근거가 없음 | 출처 요구가 없음 | 문장마다 원문 근거를 붙이라고 재요청 |
| 담당자·날짜를 AI가 채움 | 빈칸 규칙이 없음 | 확인되지 않은 값은 `미확인`으로 표시하고 다음 단계로 넘기지 않음 |

## [75–90] 공유·정리

### 공유 (10분)

2~3명이 아래 세 가지를 공유합니다.

- 내가 읽은 원본과 범위
- 가장 유용했던 요약 한 줄과 근거 문장
- 아직 확인할 수 없었던 빈칸 하나

### 마무리 멘트 (5분)

> "오늘은 자동화를 완성한 날이 아니라, 자동화가 시작될 원본을 확인한 날입니다."
>
> "다음 회차에는 오늘 읽은 원본을 업무 데이터의 한 행으로 바꿉니다. 그때도 근거 없는 값은 넣지 않습니다."

### 숙제

- AI에게 읽히면 도움이 될 업무 원본 1개
- 그 원본에서 반복해서 확인하는 값 3개
- 2회차에 만들 한 행의 이름 1개

## 이 회차가 실패하는 경우

| 신호 | 의미 | 다음 회차 조치 |
|---|---|---|
| 원본을 못 찾은 사람이 많음 | 연결 준비가 부족함 | 2회차 전 개별 연결 지원 |
| 근거 없는 요약이 많이 남음 | 읽기보다 생성에 집중함 | 2회차 시작 전 근거 검수 10분 추가 |
| 각자 다른 자료를 너무 많이 읽음 | 범위가 커짐 | 지정한 원본 1건으로 다시 맞춤 |
| 다음 한 행을 정하지 못함 | DB 구조와 연결되지 않음 | 2회차 Supabase 미니랩에서 사례로 다시 선택 |
