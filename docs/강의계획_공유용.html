업무를 연결하는 AI

Notion·Asana·Slack의 실제 값을 가져와 사람이 확인해 고치고, 같은 자리에 다시 저장하는 4주 과정. 전사 크루(비개발) 대상이며, 참가자 전용 워크북 웹앱에서 실습이 진행됩니다.

대상 전사 크루 · 비개발
구성 4회 × 90분
방식 워크북 웹앱 · 실제 SaaS 연동
정원 12명 내외 (조교 1명)

이 강의가 푸는 문제

AI 도구는 이미 다들 쓰고 있습니다. 그런데 내 업무에 붙이는 순간 대부분 멈춥니다. 멈추는 이유는 프롬프트를 못 써서가 아니라, AI와 업무 도구 사이를 사람이 복붙으로 나르고 있기 때문입니다.

노션 열기 → 드래그 → 복사 → AI → 결과 복사 → 다시 노션. 이 방식은 세 군데서 막힙니다. 양(수십 건은 복붙이 불가능하다), 최신성(붙여넣는 순간 이미 과거다), 반복 비용(매주 같은 일을 처음부터 한다).

이 강의는 나르는 일을 없앱니다. 워크북이 편집 작업대가 되어 SaaS 원본을 가져오고, 사람이 확인해 고치고, 같은 위치에 다시 저장합니다.

관통 원리 — 네 단계

4주 내내 반복되는 뼈대는 하나입니다. 매 회차 이 흐름을 한 바퀴씩 돕니다.

01
가져오기
Collect

Notion 페이지·Asana 프로젝트·Slack 채널에서 실제 값을 워크북으로

02
다듬기
Structure

근거·담당자·상태·마감일처럼 사람이 확인하고 고칠 칸을 분명히

03
반영하기
Sync

변경 전후를 미리보기로 확인한 뒤 같은 태스크·문단·메시지에 저장

04
이어쓰기
Reuse

저장된 기록을 다시 읽어 레시피와 다음 자동화의 재료로

“어디서 가져와, 무엇을 고치고, 어디에 다시 저장할 것인가.” — 이 한 문장이 4주의 전부입니다.

회차 구성

1회차
AI에게 업무 원본을 읽히는 날 · 연결

내 계정 권한 안에서 AI가 읽을 수 있는 원본을 목록으로 만들고, 실습장(각자 복제한 Notion 템플릿)의 문단을 워크북으로 가져와 작은 수정을 같은 문단에 저장합니다. 도입에서 강사가 지난 5월 같은 일을 하려고 만들었던 크롬 확장 프로그램 651줄을 보여주고 시작합니다 — “저는 2주 걸렸습니다. 오늘 여러분은 버튼 하나로 합니다.”

완성물 내 권한 안의 원본 목록 + Notion 문단 첫 수정 저장
2회차
흩어진 기록에 구조를 더하는 날 · 구조

회의록에서 액션아이템 후보를 규칙 없이 넓게 뽑고(20개+), 규칙 — 근거문장 필수, 논의만 된 건 제외 — 을 넣어 다시 뽑아(13~15개) 차이를 눈으로 확인합니다. 지어낸 항목을 잡아내는 게 이 회차의 전부입니다. 결과는 DB에 명시 저장하고, 학습 기록 한 건을 클래스 플랫폼에 남깁니다 — 워크북에서 다른 서비스의 DB에 직접 쓰는 첫 경험입니다.

완성물 근거가 붙은 액션아이템 표 + 클래스 학습 기록 1건
3회차
Asana·Notion·Slack을 실제로 연결하는 날 · 연동

봇 토큰은 운영자가 서버에만 두고, 수강생은 대상(프로젝트·페이지·채널)만 지정합니다 — 권한은 관리자에게, 대상 지정은 실무자에게라는 구분 자체가 교육 포인트입니다. Asana 태스크와 Notion 문단을 수정 저장하고, Slack은 보내기(작성 → 미리보기 → 전송 → 같은 메시지 수정)와 받기(사람이 채널에 쓴 메시지를 수신함으로)를 따로 연습합니다.

완성물 세 SaaS 수정 저장 영수증 + 내 연결 레시피
4회차
내 업무 흐름을 연결하는 날 · 정착

승인 절차 없이 오늘 바로 쓸 수 있는 개인 루틴(수신함 정리·일일 로그·주간 회고)과 파일 정리 자동화 규칙을 만든 뒤, 각자 자기 업무 하나를 연결 설계서로 완성하고 2인 1조(타 팀)로 상호 리뷰합니다. 3주간의 기록 전체를 파일로 내보내 다음 실행의 재료로 가져갑니다.

완성물 내 업무 연결 설계서 + 1~4회차 기록 내보내기

실습 도구 — 참가자 전용 워크북

실습은 전부 참가자 전용 웹앱에서 진행됩니다. 회사 구글 계정(@boosters.kr)만 로그인할 수 있습니다.

SaaS 원본→워크북에서 수정→미리보기 · 확인→같은 SaaS에 저장→기록 재조회

참가자에게

  • 회차별 실습·설계서가 한 곳에, 진행률이 눈에 보임
  • 입력은 본인과 강사만 열람 — 동료에게 공개되지 않음
  • 외부 도구에 쓰는 동작은 미리보기 → 한 번 더 확인을 거쳐야 실행
  • 저장은 하단 [모두 저장] 버튼으로 확정 — 저장 전 초안도 유실되지 않음

운영·보안

  • Asana·Notion·Slack 봇 토큰은 서버에만 — 수강생 화면에 노출되지 않음
  • 수정 저장 대상은 복제본·샘플 태스크·봇 메시지로 한정
  • 로그인 6시간 후 자동 로그아웃, 도메인 제한 4중

왜 ‘노말한 방법’인가

같은 업무를 코드로 구현해본 강사의 실사례를 대조하며 시작합니다.

업무코드로 한 방식이 강의 방식회차
행사 퀴즈 콘텐츠크롬 확장 프로그램 651줄 + Sheets API 연동워크북 버튼으로 Notion 문단 가져오기1
부자재 이력 관리Next.js + DB 테이블 + 노션 자동 생성 API워크북에서 수정 → 같은 SaaS에 저장3
경영 대시보드집계 쿼리 + 캐시 DB + 차트 화면기록을 다시 읽어 리포트·레시피로4
시스템 개발은 규모·신뢰성·권한 통제가 필요할 때 합니다. 대신 몇 달이 듭니다. 이 강의 방식은 90분에 연결하고, 안 맞으면 버립니다. 판단 기준 한 줄 — 매일 100명이 쓰면 시스템, 매주 나 혼자 쓰면 연결.

매 회차 90분

시간블록내용
0–10체크인지난주 적용 사례 · 숙제에서 막힌 지점 공유
10–25개념화이트보드에 가져오기 → 다듬기 → 반영하기 → 이어쓰기
25–40라이브 데모강사가 워크북에서 실제 실행 — 실패도 그대로 보여준다
40–75실습각자 워크북 진행. 강사 + 조교가 순회
75–90공유·정리완성물 공유 + [모두 저장] 전원 확인 + 숙제

운영 원칙

  • 실습이 전체의 40% 미만이면 그 회차는 실패다. 개념 설명이 길어지면 잘라낸다.
  • 데모에서 연동이 엉뚱하게 나오면 고치지 말고 그대로 보여준 뒤 같이 진단한다.
  • 회차 종료 전 저장 바가 비었는지 전원 확인한다 — 완성물이 곧 기록이다.

가장 큰 리스크 — 초기 연결

  • 연결 준비 체크리스트를 강의 3일 전 배포하고, 미완료자는 강사 화면에서 확인해 개별 지원.
  • 실습장 템플릿·샘플 Asana 프로젝트·Slack 테스트 채널은 강사가 사전 준비.
  • 당일 연결 실패자에겐 샘플 소재로 동일 실습이 가능하게 설계.

안전 규칙

매 회차 첫 화면에 이 네 줄을 그대로 띄웁니다.

01긁지 않는다 — 개인 연락처, 급여·평가, 계약 단가, 미공개 재무. 내가 볼 수 있어도 다루지 않는다.
02쓰기 전에 본다 — 모든 SaaS 반영은 미리보기 → 한 번 더 확인 → 실행. 워크북이 이 순서를 강제한다.
03채널 발송은 사람이 누른다 — 자동 발송은 범위 밖. Slack 실습도 봇 메시지·테스트 채널만.
04실습은 복제본에서 — 수정 저장 대상은 각자 복제한 실습장·샘플 태스크·봇 메시지뿐이다.

덧붙여 매번 짚을 것 — 연결의 접근 범위는 본인 계정 권한 범위까지입니다. 내가 못 보는 페이지는 AI도 못 봅니다. 제약이자 안심 포인트입니다.

강의 후 2주가 진짜 승부처

정착 장치

  • 기록이 곧 제출 — 연동 영수증·레시피·설계서가 워크북에 그대로 남는다.
  • 기록 내보내기 — 4주치 기록을 파일 한 장으로, 다음 실행의 재료로.
  • 4주 뒤 TOP3 — 실제로 굴러가는 연결 3개를 전사 공지로 발행. 다음 기수 모집이 여기서 된다.

강사 준비물

  • 워크북 배포(Vercel + Supabase) + 서버 연결값 등록
  • 「AX 실습장」 Notion 템플릿 — 수강생 각자 복제
  • Asana 샘플 프로젝트(수정용 태스크 5개+) · Slack 테스트 채널(봇 초대)
  • 클래스 플랫폼 연동 승인(2회차) · 조교 1명
