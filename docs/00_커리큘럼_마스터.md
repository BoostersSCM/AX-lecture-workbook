# 연결해서 일하기 — 노션·슬랙·드라이브를 AI로 잇는 4주

부스터스 AX 사내 강의 · 4회 × 90분 · 전사 크루 대상(비개발)

---

## 1. 이 강의가 푸는 문제

AI 도구는 이미 다들 쓰고 있다. 그런데 **내 업무에 붙이는 순간** 대부분 여기서 멈춘다.

멈추는 이유는 프롬프트를 못 써서가 아니다. **AI가 우리 회사 데이터를 못 보기 때문**이다.
지금 대부분의 크루는 이렇게 쓰고 있다.

> 노션 열기 → 드래그 → 복사 → AI에 붙여넣기 → 결과 복사 → 다시 노션에 붙여넣기

이 방식은 세 군데서 막힌다.
1. **양** — 회의록 20건은 복붙이 불가능하다
2. **최신성** — 붙여넣는 순간 이미 과거 데이터다
3. **반복 비용** — 매주 같은 일을 매주 처음부터 한다

이 강의는 복붙을 없앤다. AI에 **커넥터**를 연결해 노션·슬랙·드라이브를 직접 읽고 쓰게 만든다.

---

## 2. 관통 원리 — 긁·정·만·보

4회차 내내 반복되는 뼈대는 하나다. 매 회차 이 4단계 중 한 칸씩 깊게 판다.

| 단계 | 이름 | 하는 일 | 담당 회차 |
|---|---|---|---|
| 1 | **긁기** (Collect) | 흩어진 원본을 AI가 직접 읽게 한다 | 1회차 |
| 2 | **정하기** (Structure) | 읽은 것을 정해진 형식(표·DB)에 넣는다 | 2회차 |
| 3 | **만들기** (Generate) | 형식이 잡힌 데이터로 결과물을 만든다 | 1·3회차 |
| 4 | **보내기** (Deliver) | 사람이 볼 곳(슬랙·문서)까지 배달한다 | 3회차 |

> **강의 중 반복할 한 문장**
> "AI가 못 하는 게 아니라, 우리가 **어디서 긁어서 어떤 형식으로 어디로 보낼지**를 안 정해준 것이다."

## 3. 왜 '노말한 방법'인가 — 자동화의 스펙트럼

강사(도기웅)는 같은 일을 이미 시스템으로 구현해봤다. 1회차 도입에서 이 대조를 보여주고 시작한다.

| 업무 | SCM Portal에서 한 방식 | 이 강의에서 할 방식 | 해당 회차 |
|---|---|---|---|
| 부자재 이력 관리 | Next.js + DB 테이블 + 노션 자동 생성 API | 노션 DB에 AI가 직접 등재 | 2회차 |
| 경영 대시보드 | 집계 쿼리 + 캐시 DB + 차트 화면 | 노션 DB → 주간 요약 → 슬랙 발행 | 3회차 |
| 메일 첨부 처리 | Gmail 애드온 개발 | 수신함 자동 분류 루틴 | 4회차 |
| 행사 퀴즈 콘텐츠 | **크롬 확장 프로그램 651줄** + Google Sheets API OAuth 연동 (2026-05, notion-extractor) | 노션 크루 DB → 퀴즈 3종, 코드 0줄 | 1회차 |

**핵심 메시지**: 시스템 개발은 규모·신뢰성·권한 통제가 필요할 때 한다. 개발에 6개월이 든다.
반면 오늘 배울 방식은 **90분에 만들고, 안 맞으면 버린다**. 대부분의 업무는 후자로 충분하다.

> 판단 기준 한 줄: **매일 100명이 쓰면 시스템, 매주 나 혼자 쓰면 커넥터.**

## 4. 회차 구성 한눈에

| 회차 | 제목 | 배우는 것 | 손에 쥐고 나가는 것 |
|---|---|---|---|
| 1 | **복붙을 그만두는 날** | 커넥터 연결, 긁기 | 회식 콘텐츠 3종(퀴즈·좌석표·이름표) |
| 2 | **흩어진 기록을 표로** | 형식 지정, 안전한 쓰기 | 회의록에서 뽑은 내 업무 카드 5개 |
| 3 | **보고를 자동으로** | 가공, 발행, 재사용 | 우리 팀 주간 리포트 템플릿 + 실제 발행 1회 |
| 4 | **내 것으로 만들기** | 개인 루틴, 케이스 설계 | 내 업무 자동화 설계서 1장 |

## 5. 매 회차 공통 90분 타임테이블

| 시간 | 블록 | 내용 |
|---|---|---|
| 0–10 | 체크인 | 지난주 적용 사례 1~2명 공유 (1회차는 자기소개 대신 "내가 제일 자주 하는 반복 업무") |
| 10–25 | 개념 | 슬라이드 최소. 화이트보드에 긁·정·만·보 그리기 |
| 25–40 | 라이브 데모 | 강사가 실제로 실행. **실패도 그대로 보여준다** |
| 40–75 | 실습 | 각자 실행. 강사 + 조교 1명이 순회 |
| 75–90 | 공유·정리 | 완성물 2~3개 화면 공유, 숙제 안내 |

**운영 원칙**
- 실습 시간이 전체의 40% 미만이면 그 회차는 실패다. 개념 설명이 길어지면 잘라낸다.
- 데모에서 AI가 엉뚱한 답을 내면 **고치지 말고 그대로 보여준 뒤** 왜 그랬는지 같이 진단한다. 이게 가장 기억에 남는다.
- 매 회차 슬랙 `#부스터스-AX`(가칭)에 완성물 스레드를 열고 각자 결과를 올린다.

## 6. 1회차 — 복붙을 그만두는 날

**주제**: 커넥터로 노션을 직접 읽게 하고, 행사 퀴즈 콘텐츠를 만든다
**왜 행사 콘텐츠로 시작하나**: 업무 부담이 0이고, 결과가 재미있고, 실패해도 손해가 없다. 첫 성공 경험을 만드는 게 1회차의 유일한 목표다.

> **도입에 쓸 강사 실사례** — 2026년 5월, 사내 행사 퀴즈를 만들려고 노션 자기소개 43명분을 긁어야 했다.
> 그래서 크롬 확장 프로그램 `notion-extractor`를 만들었다 — MV3, 651줄, Google Sheets API OAuth 연동, 페이지를 열면 시트에 자동 적재.
> 거기서 나온 게 WHO AM I(힌트 3단 차등점수) · 인물 퀴즈 192문 + 크로스 퀴즈 50 · 명언 퀴즈 50 · AI 예측 퀴즈 38인 · 이름표 36인, 그리고 진행자용 PPT v3.
> **1회차 첫 10분에 이 이야기를 한다.** "저는 2주 걸려 확장 프로그램을 만들었습니다. 오늘 여러분은 그거 없이 90분에 합니다."

### 개념 (10–25분)
- 커넥터란: AI에게 우리 워크스페이스 **열쇠를 빌려주는 것**. 열쇠는 내 권한 범위까지만 열린다 — 내가 못 보는 노션 페이지는 AI도 못 본다
- 복붙 방식 vs 커넥터 방식 비교 (위 1절 그대로)
- 안전 규칙 4가지(9절) 낭독 — 매 회차 반복

### 라이브 데모 (25–40분)
1. 노션 「😀 부스터스 크루 소개」 페이지를 AI에게 읽히기
2. "크루 명단을 부서별로 표로 정리해줘" → 즉시 표 생성
3. **일부러 실패시키기**: "우리 회사 전 직원 연봉 정리해줘" → 접근 못 하는 이유 설명 (권한 = 내 권한)

### 실습 (40–75분) — 퀴즈 콘텐츠 3종

- **A. WHO AM I 15문항** — 힌트 3개, 3점/2점/1점 차등. *소개글에 없는 건 쓰지 말 것*
- **B. AI 예측 퀴즈 10인** — 소개글에 **없는** 것을 추측해서 쓰게 한다. *지어내는 게 목적*
- **C. 크로스 퀴즈 10문항** — 두 사람 이상의 공통점 + **근거 문장 필수**

각 과제 프롬프트는 `02_프롬프트_카드.md` 1회차 섹션에 그대로 복사해 쓴다.

> **A와 B를 나란히 놓는 것이 이 실습의 설계 의도다.**
> A는 "지어내면 안 되는" 과제, B는 "지어내는 게 목적"인 과제다. B가 끝나면 이렇게 묻는다 —
> *"재밌죠? 그런데 지금 AI가 없는 얘기를 지어낸 겁니다. 다음 주에 회의록으로 같은 일이 벌어지면 어떻게 될까요?"*
> C의 "근거 문장 붙이기"는 2회차 핵심 기술의 예고편이다.

### 정리 (75–90분)
- **잘 긁히는 요청 vs 안 긁히는 요청** 비교 (프롬프트 카드 참고)
- 개인정보 마스킹 규칙: 실습 산출물에는 이름 대신 이니셜, 연락처는 아예 제외
- 숙제: 내 팀 노션에서 "AI에게 읽히면 편할 것 같은 페이지" 3개를 찾아 슬랙 스레드에 올리기

## 7. 2회차 — 흩어진 기록을 표로

**주제**: 회의록에서 액션아이템을 뽑아 「업무 진행 현황」 DB에 등재한다
**핵심 전환**: 1회차는 **읽기만** 했다. 2회차부터 AI가 **쓴다**. 그래서 안전장치를 같이 배운다.

### 개념 (10–25분)
- **형식(스키마)을 서류양식으로 설명**: "AI에게 백지를 주면 매번 다른 걸 써온다. 빈칸이 정해진 양식을 주면 매번 같은 걸 써온다."
- 실습용 공용 DB 「내 업무(연습용)」 필드 — **부서 무관 9칸**. 전체 설계는 `04_실습용_샘플회의록.md` A절:

| 필드 | 형식 | 채우는 법 |
|---|---|---|
| 작업 이름 | 제목 | 동사로 끝맺기 ("장소 예약 확인", "견적서 요청") |
| 담당자 | 사람 | 회의록에 이름이 명시된 경우만 |
| 상태 | 시작 전 / 진행 중 / 완료 | 회의록에서 못 찾으면 **시작 전** |
| 마감일 | 날짜 | "다음 주까지" → 회의 날짜 기준으로 환산 |
| 우선순위 | 긴급 / 높음 / 보통 / 낮음 | 명시 없으면 **보통** |
| 유형 | 8종 중 선택 | 회의·업무요청·확인검토·자료작성·외부협의·일정조율·승인대기·기타 — **목록 안에서만** |
| 세부내용 | 텍스트 | 무엇을 어디까지 하는지 한 줄 |
| 근거문장 | 텍스트 | 회의록 원문 문장을 **그대로** 복사 |
| 출처 회의록 | 텍스트 | 회의록 제목 + 날짜 |

> **부서 전용 DB를 쓰지 않는 이유**
> 「업무 진행 현황(이퀄베리 팀)」에는 품명·품번·협력사처럼 SCM에서만 통하는 칸이 있다.
> 다른 본부 크루에게는 낯선 데다 접근 권한도 없다. 실습은 전원이 같은 출발선에 서야 하므로 **공용 DB + 공용 샘플 회의록**으로 한다.
> 이퀄베리 DB는 개념 설명 끝에 **1분짜리 실사례**로만 보여준다 — "실제로 굴러가는 팀 DB는 이렇게 생겼습니다. 칸 이름만 다르지 구조는 같습니다."

- **환각 방지 장치**: "빈칸은 비워둔 채로 가져와라. 추측해서 채우지 마라." 이 한 줄이 절반을 막는다

### 라이브 데모 (25–40분)
1. 샘플 회의록 ①(9월 부스팅데이 준비) 읽히기
2. 액션아이템만 골라 위 양식대로 표 만들기 — **각 행에 근거 문장 함께 출력**
3. 근거 문장이 없는 행 = AI가 지어낸 행. 그 자리에서 삭제하며 보여준다
4. 회의록 ①에는 함정이 4개 심어져 있다(케이터링·굿즈는 결정된 바 없음, 의자 건은 이미 처리됨, "다음 주 화요일"은 환산 필요). 데모에서 **최소 1개는 AI가 걸린다**

### 실습 (40–75분)
> 소재는 「AX 실습장」의 **샘플 회의록 3건**(부스팅데이 준비 / 팝업스토어 킥오프 / 계정·권한 정비).
> 어느 부서 크루가 읽어도 무슨 얘기인지 아는 내용으로 골랐다.

1. **긁기** — 샘플 회의록 3건 읽히기
2. **정하기** — 액션아이템 표 만들기 (근거 문장 필수)
3. **검수** — 근거 없는 행 삭제, 담당자·날짜 확인
4. **쓰기** — 각자 복제한 「내 업무(연습용)」 DB에 등재
5. (여유 있는 사람) **자기 팀 회의록**으로 같은 작업 1회 — 못 해도 무방, 숙제로 넘긴다

### 정리 (75–90분)
- **AI에게 쓰기를 시킬 때 3원칙**
  1. **미리보기 먼저** — "등재하기 전에 표로 먼저 보여줘"
  2. **한 건 먼저** — 1건 성공 확인 후 나머지
  3. **되돌릴 수 있게** — 실습은 복제본, 새로 만든 항목엔 표시 하나 붙여두기
- **함정 대조** (이 회차의 하이라이트) — `04_실습용_샘플회의록.md` E절의 함정 8개 표를 띄우고 각자 결과와 맞춰본다.
  세 건 합쳐 액션아이템 **13~15개**가 적정. 20개가 넘었다면 아무도 하기로 하지 않은 일을 넣은 것이다.
  > "그 5개를 그대로 노션에 넣으면, 다음 주에 하지도 않은 일이 지연으로 뜹니다."
- 숙제: **자기 팀 회의록**으로 같은 작업 1회. 우리 팀 회의록은 형식이 달라서 어디가 막히는지 관찰해 온다

## 8. 3회차 — 보고를 자동으로

**주제**: 업무 DB → 주간 리포트 → 슬랙 발행, 그리고 매주 재사용
**핵심 전환**: 결과물이 내 화면에만 있으면 자동화가 아니다. **남에게 도착해야** 끝난다.

### 개념 (10–25분)
- 자동화의 마지막 1마일 = 전달. 데이터 형식과 사람이 읽는 형식은 다르다
- 좋은 주간 리포트의 3분류: **완료 / 진행 중 / 지연**. 지연은 반드시 **사유와 다음 액션**을 붙인다
- 읽는 사람 기준으로 쓰기: 팀장이 30초 안에 판단할 수 있는가

### 라이브 데모 (25–40분)
> 소재는 **2회차에 각자 채운 「내 업무(연습용)」 DB**를 그대로 쓴다. 지난주 실습 결과가 이번 주 재료가 되는 구조라, 2회차를 빠진 사람도 실습장 샘플 DB로 따라올 수 있다.

1. 「내 업무(연습용)」에서 이번 주 데이터 긁기
2. 3분류 요약 생성
3. 슬랙 문체로 변환 — 이모지, 불릿, 담당자 멘션
4. **DM으로 나에게 먼저 발송** (리허설) → 확인 후 채널 발행
5. 마지막 1분: 강사의 실제 팀 리포트를 보여준다 — "칸 이름만 다르지, 여러분이 방금 만든 것과 같은 구조입니다"

### 실습 (40–75분)
1. 주간 리포트 초안 생성
2. 슬랙 문체 변환
3. 자기 자신에게 DM 발송으로 리허설
4. **레시피로 저장** — 이 요청 전체를 다음 주에 한 줄로 재실행할 수 있게 정리

### 정리 (75–90분)
- 반복 가능하게 만드는 법: 프롬프트를 문서로 저장 → 매주 붙여넣기 → 익숙해지면 정기 실행
- **채널 발행은 반드시 사람이 최종 확인.** 자동 발송은 이 강의 범위 밖
- 숙제: 다음 주 월요일에 저장한 레시피로 리포트 1회 실제 발행

## 9. 4회차 — 내 것으로 만들기

**주제**: 개인 루틴 자동화 + 각자 업무 케이스 설계
**핵심 전환**: 강사가 준 과제가 아니라 **내 업무**로 옮긴다. 정착률이 여기서 갈린다.

### 복습 (0–10분)
긁·정·만·보 3주치 복습, 완성물 셋 다시 꺼내보기

### 파트 1 — 개인 루틴 3종 (10–40분)
회사 승인 절차 없이 오늘 바로 적용 가능한 개인 단위 자동화.

| 루틴 | 하는 일 | 절약 |
|---|---|---|
| 수신함 정리 | 다운로드 폴더·카톡 받은 파일을 규칙대로 자동 분류 | 주 20분 |
| 일일 로그 | 오늘 만진 파일·받은 자료를 스캔해 하루 기록 자동 생성 | 매일 10분 |
| 주간 회고 | 일일 로그 5개를 모아 KPT 회고 초안 생성 | 주 30분 |

> 강사 실제 사례로 시연한다. "3개월째 쓰고 있고, 이제 안 쓰면 불편하다"가 가장 강한 설득이다.

### 파트 2 — 케이스 클리닉 (40–80분)
각자 **자기 업무 1개**를 가져와 설계서를 채운다. 워크시트는 `03_케이스_클리닉_워크시트.md`.

1. 개인 작성 (15분)
2. 2인 1조 상호 리뷰 (10분) — "이거 진짜 매주 하나?", "여기 사람 확인 없이 넘어가도 되나?"
3. 3명 발표 + 강사 즉석 시연 (15분)

### 정리 (80–90분)
- **하면 안 되는 것** 재확인 (아래 10절)
- 사내 지원 채널 안내, 4주 뒤 '이번 달 자동화 TOP3' 공유 예고

## 10. 안전 규칙 — 매 회차 상단 고정

> 이 4줄은 매 회차 첫 슬라이드에 그대로 띄운다.

1. **긁지 않는다** — 개인 연락처, 급여·평가, 계약 단가, 미공개 재무. 내가 볼 수 있어도 AI에 넘기지 않는다
2. **쓰기 전에 본다** — AI가 노션·슬랙에 무언가 쓰기 전에 반드시 초안을 눈으로 확인한다
3. **채널 발송은 사람이 누른다** — 전사 채널·외부 메일 자동 발송 금지
4. **실습은 복제본에서** — 실제 팀 DB·운영 채널은 실습 대상이 아니다

추가로 강의 중 명시할 것:
- 커넥터의 접근 범위 = **내 계정 권한 범위**. 권한 없는 페이지는 AI도 못 본다 (안심 포인트)
- 협력사명·단가가 섞인 자료는 요약 결과도 사내 공유 범위를 지킨다

- 조교 1명 (실습 순회용) — 참가자 12명 이상이면 필수
