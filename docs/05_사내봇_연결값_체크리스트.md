# 사내봇 연결값 체크리스트 — 운영자용

3회차 실습에서 사용할 서버 연결값입니다. **토큰은 수강생에게 공유하지 않고 Vercel Environment Variables에만 등록합니다.**
수강생은 각자 연결할 대상의 URL·ID와 권한만 준비합니다.

---

## 1. Vercel에 넣을 비밀값

| 도구 | 환경변수 | 용도 | 필요한 연결·권한 |
|---|---|---|---|
| Asana | **ASANA_TOKEN_BOT** | 기존 태스크 읽기·수정 | 봇 사용자가 대상 프로젝트의 멤버이고 태스크 쓰기 권한이 있어야 함 |
| Notion | **NOTION_TOKEN** | 기존 문단 읽기·수정 | 앱이 대상 페이지에 연결되어 있고 Read content·Update content 권한이 있어야 함 |
| Slack | **SLACK_BOT_TOKEN** | 봇 메시지 보내기·수정 | 봇이 대상 채널에 들어와 있고 `chat:write` 권한이 있어야 함 |
| Slack | **SLACK_SIGNING_SECRET** | Slack Events API 요청 서명 검증 | Vercel 수신 엔드포인트에서 원본 요청 검증에 사용 |
| Supabase | **SUPABASE_SERVICE_ROLE_KEY** | Slack 이벤트를 서버에서 `slack_events`에 저장 | Vercel에만 저장. 브라우저·수강생에게 공유하지 않음 |
| 공통 | **AX_INTEGRATION_SECRET** | Asana·Notion 조회와 Slack 발송 API의 별도 인증 | 긴 랜덤 문자열. 수강생·브라우저에 공개하지 않음 |

이미 워크북에서 사용 중인 Supabase 값도 그대로 유지합니다.

### Supabase 수신함 테이블 준비

기존 Supabase 프로젝트의 SQL Editor에서 [`supabase/schema.sql`](../supabase/schema.sql) 전체를 다시 실행합니다. `create table if not exists`와 `drop policy if exists`를 사용하므로 기존 워크북 데이터는 유지되고, `slack_events` 테이블과 사용자별 읽기 정책이 추가됩니다.

그 다음 Supabase → Project Settings → API에서 `service_role` 키를 복사해 Vercel Production의 `SUPABASE_SERVICE_ROLE_KEY`에만 저장합니다. 이 키는 브라우저·워크북·수강생에게 공개하지 않습니다.

### 권한 메모

- Asana: 봇 사용자가 프로젝트 멤버이고 태스크 읽기·쓰기 권한이 있어야 합니다.
- Notion: 기존 앱이 페이지에 연결되어 있고 Read content·Update content capability가 있어야 합니다.
- Slack 보내기: 봇이 채널에 들어와 있고 chat:write 권한이 있어야 합니다.
- Slack 개인 DM: `chat:write`와 `im:write` 권한이 있어야 하며, 사용자의 U로 시작하는 User ID로 DM 대화를 연 뒤 메시지를 보냅니다.
- Slack 받기: 공개 채널은 channels:history, 비공개 채널은 groups:history 계열 이벤트 권한을 확인합니다.

### 배포된 API 주소

| 기능 | 주소 | 호출 방식 |
|---|---|---|
| Asana 태스크 읽기·생성·수정 | /api/integrations/asana/tasks?projectGid=... | GET·POST·PUT / 워크북 로그인 세션 또는 X-AX-Integration-Secret |
| Notion 페이지 읽기·문단 추가·블록 수정 | /api/integrations/notion/page?pageId=... | GET·POST·PATCH / 워크북 로그인 세션 또는 X-AX-Integration-Secret |
| Slack 메시지 보내기·수정 | /api/integrations/slack/send | POST·PATCH / 워크북 로그인 세션 또는 X-AX-Integration-Secret |
| Slack Events API 받기 | /api/slack/events | Slack 서명 헤더 |

| 환경변수 | 용도 |
|---|---|
| **SUPABASE_URL** | 로그인·워크북 DB 주소 |
| **SUPABASE_ANON_KEY** | 브라우저에서 RLS 범위로 접근하는 공개 키 |
| **SUPABASE_SERVICE_ROLE_KEY** | Vercel 서버가 Slack 이벤트를 저장하는 비공개 키 |

> 토큰을 NEXT_PUBLIC_ 또는 PUBLIC_ 이름으로 만들지 않습니다. 브라우저에 내려가는 값은 공개값으로 취급해야 합니다.

## 2. 수강생이 준비할 값

| 도구 | 수강생이 적을 값 | 준비 방법 |
|---|---|---|
| Asana | **Project GID** | 프로젝트 URL의 숫자 ID 또는 운영자가 알려준 GID |
| Notion | **Page ID** | 페이지 URL에서 확인하거나 운영자에게 페이지 ID를 받음 |
| Slack | **Channel ID** | 채널 정보에서 확인하는 C로 시작하는 ID. 프론트의 `setup.slack_target`에 사용자별로 저장 |
| Slack | **User ID** | 프로필에서 확인하는 U로 시작하는 ID. 프론트의 `setup.slack_user_id`에 사용자별로 저장 |

> Events API Request URL은 운영자가 Slack 앱에 한 번 등록합니다. 수강생별 입력값이 아닙니다.

ID는 워크북에 적어도 되지만, 토큰 값은 워크북·Supabase·프롬프트에 적지 않습니다.

## 3. 도구별 연결 순서

### Asana

1. 수강생이 원하는 프로젝트를 고른다.
2. 프로젝트 멤버에 기존 봇 사용자를 초대한다.
3. Project GID를 확인한다.
4. 서버가 프로젝트 이름과 기존 태스크를 읽는다.
5. 수강생이 샘플 태스크를 워크북에서 고치고 미리보기 후 같은 task GID에 저장한다.

### Notion

1. 강사가 「AX 실습장」 템플릿과 복제 링크를 준비한다.
2. 수강생이 템플릿을 자기 페이지로 복제한다.
3. 페이지 우측 상단 ··· → 연결 추가에서 기존 앱을 선택한다.
4. Page ID를 확인하고 수정 실습 문단을 읽는다.
5. 수강생이 문단을 워크북에서 고치고 미리보기 후 같은 block ID에 저장한다.

### Slack 보내기

1. 수강생이 테스트 채널을 고른다.
2. 기존 봇을 채널에 초대한다.
3. Channel ID를 확인하고 A 카드의 `Slack에 보낼 메시지` 입력란을 작성한다.
4. 서버가 먼저 미리보기 결과를 만들고, 확인 후 chat.postMessage를 호출한다.
5. 응답의 channel·ts를 저장한 뒤 워크북에서 문구를 고쳐 `chat.update`로 같은 메시지에 저장한다.

### Slack 받기

1. Vercel의 공개 Events API Request URL을 Slack 앱 설정에 등록한다.
2. Slack이 보내는 url_verification challenge에 200으로 응답한다.
3. 실제 event_callback은 signing secret으로 검증한다.
4. 사람이 채널에 직접 쓴 이벤트를 받고 `channel_id`를 기록한다. 사용자별 대상 Channel ID는 워크북 설정에 저장해 후속 저장·처리 범위를 정한다. 봇 자기 메시지는 중복 방지를 위해 제외한다.
5. event_id·channel_id·slack_user_id·text·event_ts를 `slack_events`에 저장한다.
6. Slack에는 빠르게 200을 돌려주고, 오래 걸리는 후속 작업은 별도로 처리한다.

---

## 4. 3회차 성공 기준

- [ ] Asana: 워크북에서 고친 값이 같은 task GID에 저장되었다.
- [ ] Notion: 워크북에서 고친 문장이 같은 block ID에 저장되었다.
- [ ] Slack 보내기: 워크북에서 고친 문구가 같은 channel·ts의 봇 메시지에 저장되었다.
- [ ] Slack 받기: 채널 테스트 메시지가 Vercel 웹훅에 도착했다.
- [ ] 3회차 워크북의 Slack 수신함에서 내 Channel ID 이벤트가 보인다.
- [ ] Slack 이벤트에서 봇 자기 메시지를 다시 처리하지 않았다.
- [ ] 각 결과에 원본 URL·ID와 사람이 확인할 항목이 남아 있다.
- [ ] Asana·Notion·Slack API가 워크북 로그인 세션 또는 AX_INTEGRATION_SECRET 없이 호출되지 않는다.

연결이 막히면 토큰을 다시 공유하지 말고, **도구명·대상 ID·응답 상태 코드·오류 문장**만 강사에게 전달합니다.
