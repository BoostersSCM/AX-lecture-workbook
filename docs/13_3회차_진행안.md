# 3회차 진행안 — 한 번의 입력으로 여러 곳에 보내는 날

**90분 · 실습 소재: 2회차에 각자 채운 「내 업무(연습용)」 → Slack·Notion·Asana 리포트**

**비유로 시작하기**: 봇은 사내 우편 분류소입니다. 같은 원본을 Slack 메시지·Notion 기록·Asana 태스크로 목적지에 맞게 포장합니다.

---

## 이 회차의 목표

**결과물이 남에게 도착하는 경험을 시킨다. 그리고 다음 주에 다시 쓸 수 있는 형태로 남긴다.**

1·2회차 결과물은 각자 화면 안에만 있었습니다. 자동화는 **전달까지 가야** 끝납니다.
동시에 이 회차에서 처음으로 "반복"을 다룹니다 — 한 번 만든 걸 매주 재사용하는 법.
2회차의 DB는 최종 목적지가 아니라 중간 허브입니다. `entries`에서 읽은 값을 목적지별 형식으로 바꿉니다.

**끝났을 때 상태**
- `entries`에서 필요한 필드만 읽어 목적지별 초안으로 변환
- Slack에 자기 자신 앞으로 리포트 DM 1건 발송 (리허설)
- 같은 데이터를 Notion 페이지와 Asana 태스크 구조로도 설명할 수 있음
- 다음 주에 붙여넣기만 하면 되는 **레시피** 1개를 손에 쥠
- "지연 사유는 AI가 채우면 안 된다"를 이해함

---

## 강사 준비물 체크

- [ ] 2회차 등재를 못 끝낸 사람용 **완성본 DB** 준비 (실습장에 「내 업무(연습용)_완성본」) — 없으면 이 회차를 아예 못 따라옵니다
- [ ] 강사 본인의 실제 팀 주간 리포트 1장 (마지막 1분용)
- [ ] 슬랙 DM 발송 데모 준비 — **채널이 아니라 DM**임을 재확인
- [ ] 2회차 숙제 스레드(자기 팀 회의록에서 막힌 지점) 미리 읽어두기
- [ ] 레시피 저장할 곳 안내 준비 (개인 노션 페이지 또는 메모 앱)

## [0–10] 체크인

**하는 것**: 2회차 숙제에서 나온 "막힌 지점"을 3~4개 읽습니다. 예상되는 것들:

| 흔한 답변 | 강사의 응답 |
|---|---|
| "우리 팀 회의록은 형식이 제각각이라 못 뽑았다" | "정상입니다. **원본이 지저분하면 형식을 더 빡빡하게** 줘야 합니다. 오늘 그 감을 더 잡습니다." |
| "회의록이 아예 없다 (구두로만 함)" | "그럼 긁을 게 없습니다. 4회차에서 다른 소재를 같이 찾아봅시다." |
| "노션 접근 권한이 없었다" | "권한 문제는 기술로 못 풉니다. 팀장님께 요청하세요." |

> **이 블록을 대충 넘기지 마십시오.** 숙제에서 막힌 걸 다뤄주지 않으면 숙제 제출률이 3회차부터 0에 수렴합니다.

## [10–25] 개념

### 1) 마지막 1마일 (5분)

화이트보드:
```
긁기 ──▶ 정하기 ──▶ 만들기 ──▶ [ 보내기 ]
                                    ▲
                              여기서 대부분 멈춘다
```

> "결과가 내 화면에만 있으면 그냥 조회한 겁니다. **남에게 도착해야** 일이 끝납니다.
> 그런데 데이터 형식과 사람이 읽는 형식은 다릅니다. 오늘은 그 변환을 배웁니다."

### 2) 주간 리포트의 3분류 (7분)

```
✅ 완료      — 건수 + 목록
🔄 진행 중   — 건수 + 목록 (예상 완료 시점)
⚠️ 지연      — 건수 + 목록 + [지연 사유] + [다음 액션]
```

**세 번째 줄에서 멈추고 강조합니다.**

> "지연 사유, 이거 데이터에 있습니까? **없습니다.**
> 그럼 AI가 뭘 쓸까요? 지어냅니다. '협력사 회신 지연으로 추정됩니다' 같은 걸 씁니다.
> 이걸 팀장님이 보면 어떻게 될까요?"

> "**지연 사유는 빈칸으로 받아서 내가 채웁니다.** 오늘 배우는 규칙 중 제일 중요합니다."

### 3) 읽는 사람 기준 (3분)

> "이 리포트를 받는 사람은 팀장입니다. **30초 안에 판단**이 되어야 합니다.
> 그래서 숫자 없는 형용사는 뺍니다. '많이 진행됐습니다' → '8건 중 5건 완료'."

## [25–40] 라이브 데모

### 1단계 — 긁기 (3분)
프롬프트 카드 3회차 1단계. 완료/진행/지연 3개 표가 나오는 것 확인.

### 2단계 — 요약 생성 (5분)
프롬프트 카드 3회차 2단계.

**짚을 것**: 지연 항목에 사유 칸이 **비어서** 나오는지 확인.
채워져 나왔다면 그 자리에서 지적합니다 — "이거 어디서 나온 정보죠? 지어낸 겁니다."

### 3단계 — 슬랙 문체 변환 (4분)

변환 전후를 나란히 놓고 보여줍니다.

| 변환 전 (문서체) | 변환 후 (슬랙체) |
|---|---|
| 문단, 존댓말 서술 | 제목 1줄 + 불릿, 40자 이내 |
| 담당자 이름 나열 | `@이름` 멘션 자리 |
| 지연 사유 서술 | 사유 + 다음 액션 한 줄 |

> "같은 내용인데 읽히는 속도가 다릅니다. **도착지에 맞춰 형식을 바꾸는 것**, 이게 '보내기'입니다."

### 4단계 — DM 발송 (3분) ★

```
이 내용을 슬랙에서 나 자신에게 DM으로 보내줘.
보내기 전에 최종 문구를 한 번 더 보여줘.
```

**반드시 말할 것**:
> "채널이 아니라 **저한테 보냈습니다.** 리허설입니다.
> 실제 채널 게시는 여러분이 슬랙에서 직접 붙여넣고 누르세요.
> 전사 채널로 나가는 걸 자동으로 만드는 건 이 강의에서 안 합니다."

## [40–75] 실습

### 시작 전 안내 (2분)

> "2회차 등재를 못 끝내신 분은 실습장의 **「내 업무(연습용)_완성본」**을 복제해서 쓰세요.
> 오늘은 데이터를 만드는 날이 아니라 **보내는 날**입니다."

### 1~5단계 (33분)

| 단계 | 내용 | 시간 |
|---|---|---|
| 1 | 이번 주 데이터 긁기 | 3분 |
| 2 | 3분류 요약 초안 | 8분 |
| 3 | **지연 사유를 직접 채우기** (손으로) | 7분 |
| 4 | 슬랙 문체 변환 + DM 발송 | 8분 |
| 5 | **레시피로 저장** | 7분 |

### ★ 3단계를 반드시 지키게 할 것

순회하면서 지연 사유가 채워진 화면을 보면 물어봅니다.

> "이 사유, 직접 쓰신 거예요, AI가 쓴 거예요?"

AI가 쓴 거면 지우고 다시 쓰게 합니다. **이 한 번의 경험이 3회차의 핵심입니다.**

### 5단계 — 레시피 저장 (놓치기 쉬움)

```
방금 우리가 한 1~4단계 전체를, 다음 주에 내가 한 번에 다시 쓸 수 있는
프롬프트 한 덩어리로 정리해줘.
날짜처럼 매주 바뀌는 부분은 [이번 주] 같은 대괄호 자리표시자로 남겨줘.
```

> "이걸 어디 저장하실 겁니까? **지금 정하세요.** 개인 노션 페이지든 메모장이든 상관없는데,
> 다음 주 월요일에 찾을 수 있는 곳이어야 합니다."

저장 위치를 슬랙 스레드에 적게 하면 실제로 저장합니다.

### 순회 체크포인트

**10분차** — 데이터가 안 나오는 사람 (2회차 DB가 비어 있는 경우) → 완성본으로 전환
**20분차** — 지연 사유를 AI가 채웠는지 확인
**30분차** — 레시피 저장까지 간 사람 수 확인. 절반 미만이면 전체에 5분 더 줍니다

### 자주 막히는 지점과 대응

| 증상 | 원인 | 대응 |
|---|---|---|
| "이번 주 데이터가 없다" | 2회차 등재 항목의 날짜가 과거 | "이번 주" 대신 "전체"로 조건 완화 |
| 리포트가 너무 길다 | 줄 수 제한 누락 | "15줄 이내, 각 줄 40자 이내" 추가 |
| 지연 사유를 AI가 채움 | 프롬프트에서 빈칸 지시 누락 | 3회차 2단계 프롬프트의 해당 문장 다시 확인 |
| DM이 안 보내짐 | 슬랙 커넥터 미연결 | 텍스트를 복사해 직접 붙여넣게 함. **실습 목적은 달성** |
| 멘션이 실제 멘션이 아님 | 정상 | "@이름은 자리표시자입니다. 슬랙에서 직접 바꾸세요" |
| 레시피가 너무 장황함 | 정리 지시 부족 | "이걸 반으로 줄여줘" 한 번 더 |

## [75–90] 정리

### 반복 가능하게 만드는 3단계 (5분)

```
1단계  프롬프트를 문서로 저장      ← 오늘 여기까지
2단계  매주 월요일에 붙여넣기      ← 다음 주에 하실 것
3단계  익숙해지면 정기 실행으로    ← 4회차에서 다룹니다
```

> "자동화라고 하면 3단계부터 상상하는데, **2단계만 해도 시간이 절반으로 줍니다.**
> 그리고 2단계 없이 3단계로 가면 대부분 실패합니다. 뭘 자동화할지 모르는 채로 자동화하는 거니까요."

### 공유 (5분)

DM으로 받은 리포트 중 2개를 화면에 띄웁니다. 볼 것:
- 30초 안에 상황이 읽히는가
- 지연 사유가 사람 말투인가 (AI가 쓴 문장은 티가 납니다 — "~로 추정됩니다", "~로 보입니다")

### 마무리 멘트 (3분)

> "3주 동안 긁고, 담고, 보냈습니다. 여기까지가 **제가 정해준 과제**였습니다.
> 다음 주에는 각자 **자기 업무**를 가져오십시오. 그게 마지막 회차입니다."

### 숙제 (2분) — 4회차 준비물이라 강조

> 1. 다음 주 월요일에 저장한 레시피로 리포트 **1회 실제 발행** (팀 채널이든 팀장 DM이든)
> 2. **4회차에 가져올 것** — 내가 매주 반복하는 업무 1개. 1회차 체크인에 적어둔 것 그대로여도 됩니다.
>    없으면 4회차에 할 게 없습니다.

## 시간 조절

**뒤처질 때 자르는 순서**
1. 공유 5분 → 2분
2. 실습 4단계 DM 발송 → 화면에 최종 문구 확인까지만
3. 개념 3) 읽는 사람 기준

**절대 자르지 말 것**: 지연 사유를 사람이 채우는 3단계, 레시피 저장 5단계

**시간이 남을 때**
- 같은 데이터로 **팀장용 / 본부장용** 두 버전을 만들어 비교 (같은 데이터, 다른 요약 수준)
- 리포트에 "다음 주 예정" 섹션 추가해보기

## 이 회차가 실패하는 경우

| 신호 | 의미 | 조치 |
|---|---|---|
| 레시피 저장까지 간 사람이 소수 | 반복 개념이 안 심어짐 | 4회차 시작 10분을 레시피 재작성에 할애 |
| 지연 사유를 다들 AI가 채움 | 핵심 메시지 전달 실패 | 4회차 안전 파트에서 실제 사고 사례로 다시 다룸 |
| 4회차 준비물(내 업무 1개)을 못 정함 | 케이스 클리닉이 붕 뜸 | 3회차 종료 후 개별 DM으로 1:1 확인. **4회차 전에 전원 확보 필수** |
