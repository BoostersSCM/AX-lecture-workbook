# 3회차 진행안 — Asana·Notion·Slack을 실제로 연결하는 날

**90분 · 실습 소재: 수강생이 직접 고른 Asana 프로젝트·Notion 페이지·Slack 채널**

**비유로 시작하기**: 봇은 마스터키가 아니라 **초대받은 방에서만 일하는 담당자**입니다. 프로젝트·페이지·채널마다 출입 권한을 확인해야 합니다.

---

## 이 회차의 목표

기존에 만들어진 토큰을 수강생에게 나눠주는 것이 아니라, 서버에 보관된 봇·앱을 각자의 업무 대상에 연결합니다. 이 워크북을 편집 작업대로 사용해 SaaS 값을 가져오고, 고친 값을 같은 위치에 다시 저장합니다.

끝났을 때 수강생은 다음을 직접 확인합니다.

- Asana: 기존 태스크를 가져와 이름·설명·마감일·완료 상태를 수정 저장한다.
- Notion: 「AX 실습장」의 기존 문단을 가져와 같은 블록에 수정 저장한다.
- Slack 보내기: 봇 메시지를 보낸 뒤 같은 channel·ts의 메시지를 다시 수정한다.
- Slack 받기: 채널 메시지가 Vercel Events API 엔드포인트로 들어오는 것을 확인한다.
- 세 연결에 원본 ID·응답·사람의 확인 지점을 남긴다.

토큰 값은 워크북·프롬프트·Supabase에 적지 않습니다. 운영자가 Vercel 환경변수에만 넣습니다.

---

## 강사 준비물 체크

- [ ] Vercel 환경변수: AX_INTEGRATION_SECRET, ASANA_TOKEN_BOT, NOTION_TOKEN, SLACK_BOT_TOKEN, SLACK_SIGNING_SECRET
- [ ] Supabase 운영 환경변수는 기존 값 그대로 유지
- [ ] Slack Events API Request URL 공개 엔드포인트
- [ ] Slack 앱의 Event Subscriptions와 필요한 message 이벤트 권한
- [ ] 테스트용 Slack 채널
- [ ] Asana 봇 사용자 계정과 초대 방법
- [ ] 수정 가능한 샘플 태스크가 있는 Asana 실습 프로젝트
- [ ] 「AX 실습장」 Notion 템플릿과 수강생용 복제 링크
- [ ] Notion 기존 앱의 Read content·Update content 권한과 연결 추가 방법
- [ ] 각 API가 토큰 값을 응답에 포함하지 않는지 확인

## [0–10] 연결값 확인

수강생이 작성한 연결 준비 내용을 화면에 띄웁니다.

| 확인할 값 | 예시 | 비밀값인가 |
|---|---|---|
| Asana Project GID | 프로젝트 URL의 숫자 ID | 아니오 |
| Notion Page ID | 페이지 URL의 ID | 아니오 |
| Slack Channel ID | C로 시작하는 채널 ID. 각자 워크북에 저장 | 아니오 |
| Slack Events API Request URL | 운영자가 Slack 앱에 등록한 Vercel 공개 URL | 수강생 입력 불필요 |
| Asana·Notion·Slack 토큰 | 운영자 Vercel 환경변수 | 예, 공유 금지 |

> 수강생이 토큰을 채팅창에 붙여넣으려 하면 멈춥니다. “토큰은 서버에 있고, 우리는 대상 ID만 건넵니다”를 반복합니다.

## [10–20] 개념

### 1) 권한은 두 겹입니다

1. 서버가 API 토큰을 가지고 있는가
2. 봇·앱이 실제 프로젝트·페이지·채널에 초대되어 있는가

둘 중 하나라도 없으면 401·403 또는 접근 불가가 나옵니다. 토큰이 있다고 모든 자료를 읽을 수 있는 것은 아닙니다.

### 2) 가져오기·수정 저장·받기

- 가져오기: 대상 ID를 받아 원본의 제목·내용·상태와 항목 ID를 워크북으로 가져온다.
- 수정 저장: 변경 전후를 미리 본 뒤 같은 task GID·block ID·channel+ts에 저장한다.
- 받기: 외부 서비스가 보낸 이벤트를 검증하고 필요한 값만 저장한다.

### 3) Slack 이벤트의 안전장치

- url_verification challenge에는 200으로 응답한다.
- 실제 이벤트는 signing secret으로 요청을 검증한다.
- 대상 채널이 아니면 처리하지 않는다.
- 봇이 보낸 메시지는 다시 처리하지 않는다.
- Slack에는 빠르게 200을 돌려주고 무거운 작업은 분리한다.

## [20–40] 라이브 데모

### 1단계 — Asana 기존 태스크 수정 저장 (7분)

1. 강사가 테스트 프로젝트를 연다.
2. 프로젝트 멤버에 기존 봇을 초대한다.
3. Project GID를 서버에 전달한다.
4. 프로젝트의 기존 태스크를 워크북으로 가져온다.
5. 샘플 태스크의 이름·마감일·완료 상태를 고치고 수정 전후를 미리 본다.
6. 확인 버튼으로 같은 task GID에 저장하고 Asana 화면에서 다시 확인한다.

**강사 멘트**

> “봇 토큰이 있어도 프로젝트에 초대되지 않았다면 못 읽습니다. 토큰은 열쇠이고, 프로젝트 초대는 출입명부입니다.”

### 2단계 — Notion 기존 문단 수정 저장 (7분)

1. 강사가 「AX 실습장」 복제본의 우측 상단 ··· 메뉴를 연다.
2. 연결 추가에서 기존 앱을 선택한다.
3. Page ID로 수정 가능한 문단과 block ID를 읽는다.
4. 수정 실습 문단을 워크북에서 고치고 변경 전후를 미리 본다.
5. 같은 block ID에 저장한 뒤 Notion에서 최종 문장을 다시 확인한다.

**강사 멘트**

> “Notion은 워크스페이스 전체를 여는 게 아닙니다. 앱을 연결한 페이지부터 한 칸씩 열어줍니다.”

### 3단계 — Slack 보내기·수정·받기 (6분)

1. 봇을 테스트 채널에 초대한다.
2. Channel ID를 지정한다.
3. 메시지를 먼저 미리 보여준다.
4. 확인 후 봇이 채널에 메시지를 보낸다.
5. 워크북에서 문구를 고친 뒤 같은 channel·ts로 메시지를 수정한다.
6. 같은 채널에 AX-WEBHOOK-TEST를 직접 쓰고 워크북 수신함에서 확인한다.
7. 봇 자기 메시지는 무시되는지 확인한다.

**강사 멘트**

> “보내기는 우리가 호출하지만, 받기는 Slack이 우리 서버를 호출합니다. 이 둘을 같은 것으로 생각하지 않는 것이 오늘의 핵심입니다.”

## [40–75] 개인 실습

### 실습 1 — Asana (10분)

1. 원하는 프로젝트를 선택한다.
2. 기존 봇을 프로젝트 멤버로 초대한다.
3. Project GID를 입력한다.
4. 기존 태스크를 불러와 하나를 선택한다.
5. 이름·설명·마감일·완료 상태를 고치고 미리보기 후 저장한다.

**통과 기준**

- 봇 초대 완료
- Project GID 확인
- 기존 태스크 조회
- 같은 task GID에 수정 내용 저장
- Asana 화면에서 최종 값 재확인

### 실습 2 — Notion (10분)

1. 내 「AX 실습장」 복제본을 선택한다.
2. 연결 추가에서 기존 앱을 선택한다.
3. Page ID를 입력한다.
4. 수정 실습 문단과 block ID를 불러온다.
5. 워크북에서 문단을 고치고 같은 block ID에 저장한다.

**통과 기준**

- 앱 연결 완료
- Page ID 확인
- 수정 가능한 문단과 block ID 조회
- 같은 Notion 블록에 수정 내용 저장
- Notion 화면에서 최종 문장 재확인

### 실습 3 — Slack 보내기 (7분)

1. 테스트 또는 실제 업무 채널을 선택한다.
2. 봇을 채널에 초대한다.
3. Channel ID를 입력한다.
4. 메시지를 미리 보고 확인한다.
5. 봇으로 메시지를 보낸다.
6. 워크북에서 문구를 다시 고쳐 같은 channel·ts에 수정 저장한다.

**통과 기준**

- 지정한 채널에만 도착
- 미리보기 후 전송
- 전송 결과의 channel·ts 확인
- 봇이 작성한 같은 메시지에 수정 내용 반영

### 실습 4 — Slack 받기 (8분)

1. Slack Events API Request URL을 확인한다.
2. 테스트 메시지를 채널에 쓴다.
3. 3회차 워크북의 Slack 수신함에서 이벤트를 확인한다.
4. channel_id가 내가 연결 준비에 적은 Channel ID인지 확인한다.
5. 봇 자기 메시지가 다시 처리되지 않았는지 확인한다.

**통과 기준**

- event_id·channel_id·slack_user_id·text·event_ts 확인
- 서명 검증 통과
- 내 Channel ID 이벤트가 수신함에 보임
- 봇 자기 메시지 무시

### 순회 체크포인트

| 시점 | 확인할 것 | 막히면 |
|---|---|---|
| 10분 | Asana 수정 저장 여부 | 프로젝트 멤버와 태스크 쓰기 권한 확인 |
| 20분 | Notion 수정 저장 여부 | 페이지 연결 목록과 Update content 권한 확인 |
| 30분 | Slack 보내기·수정 응답 | 봇의 채널 참여와 channel·ts 확인 |
| 35분 | Slack 이벤트 수신 | Request URL, signing secret, 이벤트 구독 확인 |

## 자주 막히는 지점과 대응

| 증상 | 원인 후보 | 대응 |
|---|---|---|
| Asana 401 | 토큰 만료·환경변수 이름 오류 | 토큰 값을 공유하지 말고 운영자가 Vercel 설정 확인 |
| Asana 403 또는 빈 결과 | 봇이 프로젝트에 초대되지 않음 | 프로젝트 멤버에 봇 초대 |
| Notion 403 | 페이지에 앱 연결 안 됨 또는 Update content 권한 부족 | ··· → 연결 추가와 앱 권한 확인 |
| Slack `cant_update_message` | 봇이 작성하지 않은 메시지를 수정하려 함 | 워크북에서 방금 보낸 봇 메시지의 channel·ts 사용 |
| Slack 메시지 전송 실패 | 봇이 채널에 없음·Channel ID 오류 | 봇 초대 후 C로 시작하는 ID 재확인 |
| Slack URL 검증 실패 | 공개 URL·challenge 응답 문제 | Request URL과 200 응답 확인 |
| Slack 이벤트가 반복됨 | 봇 자기 메시지를 다시 처리 | bot_id·subtype 필터 추가 |
| 이벤트는 오지만 내용이 안 맞음 | 다른 채널 이벤트까지 수신 | channel_id로 대상 범위 제한 |

연결이 끝내 안 되면 Asana 태스크 CSV·Notion PDF/Markdown·Slack 샘플 이벤트 JSON으로 같은 입력과 검수 흐름을 진행합니다.

## [75–90] 결과 확인과 저장

### 연결 결과 기록

각자 아래 내용을 워크북에 기록합니다.

- 원본: Asana Project GID 또는 Notion Page ID
- 목적지: Slack Channel ID
- 성공 응답: 상태 코드·channel·ts·event_id 중 확인 가능한 값
- 사람 확인: 담당자·마감일·공개 범위
- 실패 시 대체 경로: 파일·샘플 JSON·수동 게시

### 연결 레시피

다음 사람이 재실행할 수 있도록 아래 순서로 저장합니다.

1. 어떤 프로젝트·페이지·채널을 읽는가
2. 봇·앱이 어디에 초대되어 있어야 하는가
3. 어떤 필드를 가져오는가
4. 어떤 목적지 형식으로 바꾸는가
5. 사람이 무엇을 확인한 뒤 보내는가
6. 실패하면 어디로 전환하는가

### 숙제

자기 업무에서 Asana·Notion·Slack 중 하나를 골라, 이번 연결을 실제 데이터로 1회 다시 실행합니다.

## 시간 조절

**뒤처질 때 자르는 순서**

1. 결과 공유 시간을 5분으로 줄인다.
2. 선택 실습인 Notion 새 문단 추가와 Asana 새 태스크 생성은 생략하고, 기존 항목 수정 저장에 집중한다.
3. Slack 이벤트는 샘플 JSON 검수로 전환한다.

**절대 자르지 말 것**

- 토큰과 대상 ID 분리
- Asana·Notion 권한 초대 확인
- Slack 서명 검증과 봇 자기 메시지 제외
- 연결 레시피 저장
