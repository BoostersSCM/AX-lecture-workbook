# 3회차 진행안 — Asana·Notion·Slack을 실제로 연결하는 날

**90분 · 단계: 연동 · 워크북 `/session?n=3`**

> v2 — "리포트를 만들어 슬랙에 보낸다"에서 **세 SaaS를 실제로 왕복하는 연동 실습**으로 바뀌었습니다.
> 봇 토큰은 운영자가 Vercel 서버에만 두고, 수강생은 대상만 지정합니다 — 이 구조 자체가 첫 교육 포인트입니다.

---

## 이 회차의 목표

**세 SaaS에서 "가져오기 → 수정 → 미리보기 → 같은 자리에 저장"을 반복해 몸에 붙이고, 성공한 절차를 레시피로 남긴다.**

끝났을 때 상태:
- Asana 태스크 수정 저장 영수증(s3.asana_update) + Notion 문단 수정 저장 영수증(s3.notion_update)
- Slack A(보내기→같은 메시지 수정) 완료, B(수신함) 확인
- **내 연결 레시피**(s3.recipe: 원본·권한·목적지·검수 절차) 저장 + 4회차에 가져올 내 업무 결정(s3.next_case)

## 강사 준비물 체크

- [ ] Vercel 서버 키 5종 동작 확인 — `ASANA_TOKEN_BOT` `NOTION_TOKEN` `SLACK_BOT_TOKEN` `SLACK_SIGNING_SECRET` `AX_INTEGRATION_SECRET` (+ 수신함용 `SUPABASE_SERVICE_ROLE_KEY`)
- [ ] Asana 샘플 프로젝트에 **수정해도 되는 태스크 5개+** (전원이 같은 프로젝트를 쓰면 서로 덮어쓸 수 있음 — 태스크를 넉넉히, 이름에 번호)
- [ ] Slack 테스트 채널에 봇 초대 + Events API 구독 확인 (채널에 직접 한 줄 써서 수신함에 뜨는지)
- [ ] 강사 리허설: Asana·Notion·Slack A/B 각 1회 완주

## 타임테이블

| 시간 | 블록 | 핵심 |
|---|---|---|
| 0–10 | 체크인 | 2회차 숙제(막힌 지점) 3~4개 다루기 |
| 10–25 | 개념 | 실습 0 — 토큰은 서버에, 대상은 수강생이 |
| 25–40 | 데모 | Asana 왕복 1회 + Slack A/B 구조 설명 |
| 40–75 | 실습 | Asana → Notion → Slack A → (B) → 레시피 |
| 75–90 | 정리 | 같은 원본, 세 목적지 + [모두 저장] |

## [0–10] 체크인

숙제(자기 회의록에서 막힌 지점)를 3~4개 읽고 짧게 답한다. 이 블록을 건너뛰면 숙제 제출률이 무너진다.

## [10–25] 개념 — 실습 0

화이트보드:
```
[수강생] 대상 지정(프로젝트·페이지·채널)   [운영자] 토큰 (Vercel 서버)
        └────────── 워크북 /api ──────────┘
                    ↓ 미리보기 → 확인 → 실행
              같은 태스크·문단·메시지에 저장
```
> "여러분 화면 어디에도 토큰이 없습니다. 회사에서 자동화를 만들 때도 이 구분 — **권한은 관리자에게, 대상 지정은 실무자에게** — 이 기본입니다."

Slack만 방향이 둘임을 예고: **A. 워크북→Slack**(우리가 호출) / **B. Slack→워크북**(Slack이 우리 서버를 호출).

## [25–40] 데모

1. **Asana 왕복**: [수정할 태스크 불러오기] → 마감일 하나 수정 → [수정 미리보기](전/후 대비) → [확인하고 저장] → **Asana 탭에서 같은 태스크가 바뀐 것** 확인
2. **Slack A**: 메시지 작성 → [전송 미리보기] — **미리보기가 버튼 바로 아래에 뜬다**. 확인 후 전송 → Slack에서 봇 메시지 확인 → 같은 메시지를 워크북에서 수정 저장
3. **Slack B**: 조교(또는 수강생 1명)가 채널에 직접 한 줄 → 수신함 새로고침 → 도착. "이번엔 Slack이 우리 서버를 불렀습니다."

## [40–75] 실습

> "Asana → Notion → Slack A 순서로. Notion은 1회차에 해봤으니 빠를 겁니다.
> **끝나면 반드시 레시피 칸** — 오늘 성공한 절차를 다음 주의 내가 쓸 수 있게."

순회 체크포인트:
- **10분** — Asana 대상(GID) 미입력자, "수정할 태스크를 찾지 못했습니다"(샘플 태스크 소진) 확인
- **25분** — Slack A에서 미리보기 없이 두 번 누르는 사람: 버튼 문구가 '확인하고 전송'으로 바뀌는 걸 짚어줌
- **35분** — 레시피 칸 작성 시작했는지. **이게 없으면 오늘은 클릭 연습으로 끝난다**

막힘 대응:
| 증상 | 대응 |
|---|---|
| `AX_INTEGRATION_SECRET 미설정` / 401 | 운영 측 문제 — 강사가 Vercel 환경변수 확인 |
| Asana 403 | 봇 토큰이 그 프로젝트에 접근 권한 없음 — 샘플 프로젝트 URL인지 확인 |
| Slack 전송 실패 `not_in_channel` | 봇이 채널에 초대되어 있는지 |
| 수신함이 비어 있음 | A에서 봇이 보낸 메시지는 제외될 수 있음 — **사람이 직접** 쓴 메시지로, Channel ID 일치 확인 |
| 서로 같은 태스크를 수정 | 태스크 이름에 자기 이니셜을 붙이게 안내 |

## [75–90] 정리

- 실습 5(같은 원본을 세 목적지에 맞게): 한 사람 결과로 시연 — 같은 내용이 태스크·문단·메시지에서 어떻게 다른 모양이 되는지
- 레시피 2개 낭독 — 좋은 레시피는 "무엇을"이 아니라 **"어디서·누구 권한으로·어디에·무엇을 확인하고"**가 적혀 있다
- ★ 전원 **[모두 저장]** + s3.next_case(4회차에 가져올 내 업무) 확인 — **비어 있으면 4회차가 붕 뜬다. 종료 전 전원 확보**

## 시간 조절

자르는 순서: Slack B(시연으로 대체) → Asana 새 태스크 만들기·Notion 새 문단 추가(선택 실습) → 실습 5.
**절대 자르지 말 것**: 실습 0(토큰 구조), Asana 왕복 데모, 레시피 저장, s3.next_case 확보.
