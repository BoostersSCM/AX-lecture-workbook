# AX 강의 플랫폼 전환 계획

단일 강의 워크북 → **사내 AX 강의 플랫폼** (강의 − 기수 − 회차)

> 확정된 운영 결정 (2026-08-20)
> - **수강 모델**: 자유 참여 — 카탈로그에서 모집 중인 기수를 고르면 즉시 등록
> - **Q&A 공개 범위**: 본인 + 그 강의 강사진만 (1:1 문의형)
> - **강의 생성 권한**: 플랫폼 관리자만 생성, 강사는 지정받아 운영
> - **편집기 수준**: 폼 기반 블록 편집기 (비개발 강사 사용 가능)

---

## 1. 목표와 원칙

**목표** — 「업무를 연결하는 AI」처럼 워크북이 딸린 사내 강의를, 다른 강사도 코드 없이 만들고 운영할 수 있는 플랫폼.

**원칙**
1. **무중단 이전** — 기존 강의·기수·수강생 기록(entries)은 한 건도 잃지 않고 새 구조의 첫 강의가 된다
2. **콘텐츠는 DB, 코드는 렌더러** — 지금 `content.js`에 하드코딩된 문항·프롬프트·작업대 배치를 전부 DB(blocks)로 옮긴다. 강의를 새로 만들 때 배포가 필요 없어진다
3. **기존 자산 재사용** — 연동 작업대(Asana·Notion·Slack), MCP, 개방 게이트, 수동 저장, 수강생 뷰는 강의 파라미터만 받는 공용 모듈로 승격
4. **스택 유지** — 순수 HTML+ESM+CDN, Supabase RLS, Vercel. 프레임워크 도입 없음

## 2. 정보 구조와 URL

```
플랫폼
└─ 강의 course            「업무를 연결하는 AI」, 「(예) 데이터로 말하기」…
   ├─ 강사진 course_instructors   owner / instructor
   ├─ 기수 cohort          1기, 2기… (모집중/진행/종료)
   │   └─ 수강 enrollment  수강생↔기수 (자유 참여)
   └─ 회차 session         position 순서
       └─ 블록 block        head/note/field/prompt/panel/visual/link (payload jsonb)
회차 개방 gate = cohort × session (수동 토글 ∪ 강의일 예약)
기록 entry = user × course × item_key
질문 question/answer = user ↔ 강사진 (course·session 스코프)
```

| URL | 화면 |
|---|---|
| `/` | **카탈로그** — 강의 카드(모집 중 기수 표시), 내 수강 중 강의 |
| `/c/{slug}` | 강의 홈 — 소개·회차 카드·내 진행률 (지금의 홈) |
| `/c/{slug}/session?n=` | 회차 워크북 (지금 구조 그대로, DB 블록 렌더) |
| `/c/{slug}/clinic` `/c/{slug}/setup` `/c/{slug}/prompts` | 강의 스코프로 이동 |
| `/c/{slug}/qna` | 내 질문·강사 답변 |
| `/studio` | **강의 기획(오소링)** — 관리자·강사진 전용 |
| `/studio/{slug}` | 회차 구성·블록 편집·기수/개방·Q&A 응대·통계 |
| `/my` `/onboarding` `/admin`(→플랫폼 관리) | 플랫폼 공통 |

기존 URL(`/session?n=1` 등)은 기본 강의(connect-ai)로 리다이렉트해 링크 호환을 유지한다.

## 3. 데이터 모델 (DDL 스케치)

```sql
courses(id uuid pk, slug text unique, title, subtitle, intro,
        status text check (draft|active|archived), created_by uuid, created_at)

course_instructors(course_id fk, user_id fk, role text check (owner|instructor),
                   pk(course_id, user_id))

cohorts(id uuid pk, course_id fk, number int, label text,
        recruiting bool default true, unique(course_id, number))

enrollments(cohort_id fk, user_id fk, joined_at, pk(cohort_id, user_id))

sessions(id uuid pk, course_id fk, position int, title, tag, goal,
         unique(course_id, position))

blocks(id uuid pk, session_id fk, position int, type text, payload jsonb)
-- field payload: {key,kind,label,hint,required,rows,options,readonly,...}
-- prompt payload: {title,note,body,context[],output}
-- panel payload:  {panel:'notion-editor'|'asana-editor'|'slack-lab'|'save-entry'|..., params:{...}}

gates(cohort_id fk, session_id fk, open bool default false, open_date date,
      pk(cohort_id, session_id))  -- 최종 개방 = open ∪ (open_date 하루 전 0시 KST 도달)

-- 기존 테이블 확장
entries  + course_id uuid  → pk(user_id, course_id, item_key)
profiles.role → 'admin' | 'member'  (플랫폼 레벨; 강의별 강사는 course_instructors)
profiles.cohort → enrollments 로 이전 후 컬럼 유지(레거시)·신규 미사용

-- Q&A (본인+강사진)
questions(id uuid pk, course_id fk, cohort_id fk, session_id fk null,
          user_id fk, body text, status text check (open|answered), created_at)
answers(id uuid pk, question_id fk, user_id fk, body text, created_at)
```

**RLS 요지**
- `is_course_instructor(course_id)` security definer 함수 신설 (기존 `is_instructor()` 패턴)
- courses/sessions/blocks: `active`는 로그인 전원 읽기, `draft`는 강사진·관리자만. 쓰기는 owner·관리자
- gates: 읽기 전원 / 쓰기 강사진
- enrollments: 본인 insert(모집 중 기수만), 읽기 본인+강사진
- entries: 본인 전권 + **그 강의 강사진 읽기** (현재 "모든 강사가 모든 답 열람" → 강의 단위로 좁아짐)
- questions/answers: 작성자 본인 + 그 강의 강사진만
- mcp_keys/tokens·oauth: 변화 없음

## 4. 권한 모델

| 역할 | 어디에 | 할 수 있는 것 |
|---|---|---|
| 플랫폼 관리자 | profiles.role='admin' (허용목록 승격 유지) | 강의 생성·보관, 강사 지정, 모든 강의 운영 |
| 강의 강사 (owner/instructor) | course_instructors | 자기 강의의 회차·블록 편집, 기수·개방, Q&A 답변, 수강생 기록 열람, 통계 |
| 수강생 | enrollments | 등록 기수의 열린 회차 학습, 질문, 내 기록 |

수강생 뷰(프리뷰)는 **강의×기수** 선택으로 확장. 강사인데 다른 강의에선 수강생인 사람도 자연히 지원된다.

## 5. 마이그레이션 (무중단)

| 단계 | 내용 | 방식 |
|---|---|---|
| M1 | 신규 테이블·함수·RLS 생성 | `006_platform.sql` |
| M2 | 강의 시드 — `connect-ai` course + 강사진(ku.do owner, ch.yoo instructor) + 기존 `profiles.cohort` → cohorts/enrollments 백필 + `course_settings`(open/dates) → gates 백필 | 006에 포함 |
| M3 | **content.js → blocks 변환** — 생성 스크립트가 content.js를 읽어 INSERT SQL 파일 생성(`006b_seed_connect_ai.sql`), SQL Editor 1회 실행. content.js는 시드 원본으로 레포에 유지 | `scripts/gen-seed-sql.mjs` |
| M4 | entries에 course_id 추가·전량 connect-ai 백필·PK 교체 | 006에 포함 |
| M5 | 프론트 전환 — course 컨텍스트 로더(블록 DB fetch+캐시), 카탈로그 홈, 기존 URL 리다이렉트 | 코드 배포 |
| M6 | MCP course 스코프 — `get_exercise(course, id)` (course 생략 시 connect-ai로 하위호환) | 코드 배포 |

롤백: M5 전까지는 화면이 기존 content.js를 계속 읽으므로 SQL만 실행해도 서비스 영향 0. M5 배포 후 문제 시 이전 커밋 재배포.

## 6. 화면 설계 요점

**카탈로그(`/`)** — 강의 카드: 제목·소개·강사·모집 중 기수 뱃지·[참여하기]. 내가 수강 중인 강의는 상단 "이어서 학습".

**강의 홈(`/c/slug`)** — 지금 홈의 히어로·흐름·회차 카드를 강의 데이터로 렌더. 진행률은 (user, course) 스코프.

**스튜디오(`/studio/slug`)** — 탭 5개
1. **구성**: 회차 목록(순서 변경·추가·삭제) → 회차 클릭 시 블록 목록(위/아래 이동·추가·복제·삭제), 블록 폼 편집(type별 폼: field는 kind/label/hint/required…, prompt는 body/context/output, panel은 종류 선택+대상 키)
2. **기수·개방**: 지금 admin의 기수별 토글+강의일 그대로 (gates 기반)
3. **수강생**: 명단·진행률·답변 열람 (지금 admin 하단)
4. **Q&A**: 미답변 질문 인박스 → 답변 작성
5. **설정**: 제목·소개·상태(draft/active/archived), 강사 초대(관리자), **강의 복제**

**Q&A(`/c/slug/qna`)** — 수강생: 내 질문 목록+작성(회차 선택 옵션). 회차 페이지 하단에도 "이 회차에서 질문하기" 진입점. 답변 달리면 다음 접속 시 배지.

| 지금 | 플랫폼에서 |

## 8. 추가 기능 추천 (우선순위)

| 우선 | 기능 | 근거 |
|---|---|---|
| ★★★ | **강의 복제(fork)** | "다음 기수"가 아니라 "비슷한 새 강의"를 만드는 가장 흔한 경로. 블록이 DB니 한 번의 copy |
| ★★★ | **Q&A + Slack DM 알림** | 질문 등록 → 강사진 DM, 답변 등록 → 질문자 DM. 기존 `SLACK_BOT_TOKEN` 재사용, 응답 지연이 강의 만족도를 좌우 |
| ★★☆ | **기수 공지** | 강사가 기수별 공지 1줄 → 강의 홈 상단 + (선택) Slack. 회차 개방 안내와 결합 |
| ★★☆ | **강사 통계** | 회차별 완료율 퍼널, 문항별 응답률, 미시작자 목록 — 지금 admin 진행률의 확장 |
| ★★☆ | **수료 기준·수료 명단** | 필수 문항 N% + 설계서 완료 = 수료. 기수 종료 시 명단 내보내기(사내 보고용) |
| ★☆☆ | 회차 자료 첨부 | Supabase Storage — 슬라이드 PDF 등. 용량·권한 관리 필요해 후순위 |
| ★☆☆ | MCP 강사 도구 | `list_open_questions` 등 — 강사가 자기 Claude에서 미답변 질문 처리 |
| ★☆☆ | 기수 아카이브 | 종료 기수는 읽기 전용 잠금 + 기록 열람 유지 |
| ★☆☆ | 편집 감사로그 | 블록 변경 이력(누가·언제) — 공동 강사 운영 대비 |

## 10. 리스크와 미결

- **entries PK 교체**(M4)가 가장 민감 — 실행 전 `select count(*)` 스냅샷, 실행 후 동수 검증을 마이그레이션 스크립트에 포함
- 블록 렌더러가 DB를 읽으므로 **회차 첫 로딩 +1 쿼리** — 강의당 블록 수백 행 수준이라 무시 가능, 클라 캐시 추가
- panel 블록의 종류는 코드가 제공하는 목록에 한정 — 완전 자유형 작업대는 범위 밖(명시)
- 기존 `profiles.cohort`는 백필 후 미사용으로 남김(즉시 drop하지 않음 — 롤백 여지)
- 강의일 예약 판정은 현행처럼 클라이언트 시계(KST 환산) — P4에서 서버 판정 전환 검토
